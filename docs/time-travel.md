# Time Travel

Time Travel 默认关闭。在会话标题栏点击 **Time Travel → 开启**，或在会话历史页选择 **了解并开启**。阅读风险弹窗并确认后，接下来的用户回合会自动保存开始前与结束后的工作区检查点，排队请求同样适用。设置中的开关也使用同一个开启确认。

## 查看与恢复

在会话历史列表点击会话右侧的时间线图标。时间线显示真实请求、助手回复、工具结果和代码检查点，支持加载更早记录及切换历史分支。旧会话可以查看消息，但开启前未保存的代码不能补录。

- **恢复代码**：将整个工作区内纳入快照的文件恢复到检查点，对话保持当前位置。
- **恢复对话**：在同一个会话中切换到所选位置，后续内容仍保留在原分支；文件保持现状。
- **恢复两者**：先恢复文件，再切换对话。如果对话切换失败，界面会明确说明代码已恢复、对话未恢复。

恢复代码前会列出将新增、覆盖和删除的文件。确认期间发生文件改动，需要重新预览。执行前自动保存 **恢复前备份**，它会显示在该会话的各分支时间线中，便于恢复本次覆盖前的文件。损坏的快照会在写文件前被拒绝；写入失败时尝试回滚，并显示结果。恢复前应暂停同工作区的其他会话、后台作业与外部编辑。已归档会话需先取消归档才能恢复对话。

对话分支选择会持久保存，重启后继续使用所选分支。代码快照独立于 Git，不提交代码、不移动 HEAD，也不改暂存区。数据库、网络请求、已发送消息和其他外部操作无法撤销。

## 文件范围与开销

快照覆盖整个工作区，因此也包含手工编辑和其他会话的文件修改。Git 工作区保存已跟踪文件和未忽略的新文件；普通文件夹遵循 `.gitignore`，默认排除 `node_modules`。额外排除规则在设置中逐行填写，使用 Git ignore 语法。Git 元数据始终排除。空目录不单独保存。

文件读取、哈希和压缩会消耗时间、CPU 与磁盘，大文件多的项目开销更明显。文件内容以哈希去重并压缩存储；未被排除的敏感文件也会进入快照。快照保存在各执行环境的 Studio 配置目录下 `time-travel/`，不会上传到模型服务，也不在本机与远程主机之间传输代码副本。

时间线读取轻量摘要，新检查点只读取上一份完整快照，恢复时读取所选快照。旧检查点首次查看时会逐个建立摘要缓存，可能增加一次等待；完整快照格式和恢复内容保留，之后查看历史不会再将所有检查点的文件列表同时加载进内存。

快照不是运行中工作区的原子文件系统快照：外部程序可以同时写文件。检测到采集期间文件变化时，该检查点失败并提示，对话仍可继续。不要把检查点当成外部系统的事务备份。

## 设置与远程环境

在 **设置 → 常规与通知 → Time Travel** 调整：

- 全局开关：默认关闭。关闭后停止新快照与自动清理、隐藏时间线和恢复按钮；旧快照保留，仍可在设置中手动清除。
- 保留期限：默认永久，可选择 30、90、365 天或自定义天数。启用期间在快照边界按天清理过期快照；共享内容只在没有快照引用后删除。
- 排除规则：可在开启前配置。
- 快照存储：显示当前执行环境的检查点数和实际存储量，清除需要再次确认，且包括恢复前备份。

设置同步到已连接的远程 Host；未连接环境在重连时同步。设置页显示未同步状态，旧 Host 需要更新。正在执行的恢复先完成，再应用关闭操作。恢复对话需要支持精确分支恢复的新版 Runtime；旧版会给出升级提示。
