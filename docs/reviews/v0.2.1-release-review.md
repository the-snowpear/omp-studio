## 发布审查补充修复

1. **真实鼠标操作会关闭「更多模型」。** `onMouseEnter` 已经展开列表，随后的 `onClick` 又反转状态将其关闭。点击改为调用现有 `keepFlyoutOpen`；移出、Esc 和菜单外点击仍负责关闭。将现有新建／恢复会话选模型测试改成「鼠标移入 → 点击 → 选择模型」：修复前两条均失败，修复后通过。该补充修复为 `ae87bde`。
2. **命令行指定的签名身份被忽略。** `runtime-artifact.mjs` 将 `--signing-key`、`--key-id` 存成带连字符的属性，生成器却读取驼峰属性，导致回退到默认本地密钥。修正参数映射后，用独立测试密钥重新生成工件，产物记录正确 key ID，并通过桌面端的真实验签。CI 使用环境变量传参的路径保持兼容。修复为 `0272db6`。
3. **Runtime 版本必须随修复更新。** 基线虽然已改 Runtime 源码，仍沿用已发布的 `studio.1`。运行标准 overlay/regen 流程，生成新的 digest 并同步 `bridge-server.ts` 的版本为 `studio.2`；四份接缝补丁没有手工改写。
4. **发布说明与入口过期。** README 中“0.2.0 尚未发布、正式版仍是 0.1.x”的描述已修正；新增 0.2.1 发布页、升级说明及本记录，统一工作区版本和 lockfile，预览开关保持关闭。

## Windows Electron 实测

在 Windows 26H2、本机 Electron 与编译后的 `18.18.0-studio.2` 上完成五项检查。使用独立用户目录、独立工作区和本机 HTTP 测试模型，不读取日常模型凭据，不请求外部付费模型；本机验收工件使用一次性测试签名，公开工件由上述 CI 流程另行签名与审计。

1. 新建冷会话显示中性「Runtime 未启动」，鼠标移入并点击「更多模型」后可选择模型；连接结束仍保留原草稿。
2. 连续发送两条消息并收到两条测试模型回复；通过真实会话读取确认用户消息与回复持久化，且两轮属于同一会话。
3. 当前激活项目可以展开、收起、再次展开。
4. Runtime 返回的完整 v2 预测通道经过真实 preload、桌面 attach 和私有 socket 成功连接，之后释放。
5. 通过已绑定会话上下文的正式 `services.start/list/stop` 契约启动、读取和停止临时服务；运行中的 PID／owner 以及退出后保留的 owner 记录，连续三次读取均正常。预览 URL 另由上述真实 broker 回归覆盖。

最终实测报告为 `outputs/release-gui/report.json`，状态 `passed`；冷会话、两轮对话和最终工作台截图已检查，生成证据按项目约定不提交。测试使用原生文件夹选择器的替身和已完成教程偏好，因此不把它视为安装向导或首次引导验收。

## 发布方式与验证边界

正式发布使用现有 Release 工作流，选择 desktop、Windows both、stable、包含 macOS。复用已准备且签名一致的 Runtime，构建三平台桌面包和六平台 SSH 环境，所有候选通过签名、架构、文件与 digest 检查后统一发布，不修改既有 v0.2.0 资产。

源码回归和产物审计不等同于报告者机器上的实际升级。本轮不宣称覆盖 macOS GUI、UAC／Gatekeeper 首次安装、外部付费模型、真实 OAuth 登录或真实远端 SSH 登录。macOS 沿用 ad hoc 签名与未公证的现状。

「模型删除很慢」仍需按实际模型数量、配置规模和操作时序单独复现与计时，不列为本版已修复；首次启动教程的交互策略也未在本版调整。相关用户反馈继续由 [#29](https://github.com/the-snowpear/omp-studio/issues/29) 跟踪。
