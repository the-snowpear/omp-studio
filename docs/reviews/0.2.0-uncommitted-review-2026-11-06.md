## 修复与收敛

| 问题 | 最终处理 |
| --- | --- |
| 每个对话上下文各建评测协调器，却共用同一个磁盘目录 | 在 Host 中保留共享所有者，所有对话 facade 复用同一协调器；关闭对话不释放后台评测，Host 退出统一释放。 |
| 同时打开评测面板会重复创建准备 Worker；计划失败及关闭期间存在释放缺口 | 按工作区复用在途创建，启动时转移所有权；计划失败释放 Worker，退出等待在途启动，退出期间不再启动付费评测；结果刷新返回真实在途 Promise。 |
| 评测结果导出与失败项重试逐页重读整个结果文件 | 统一结果读取，一次合并行版本后分页、导出或筛选重试项；完成的写队列条目及时移除。 |
| SSH 重连后旧的上下文打开结果可能覆盖新上下文，等待中的写命令可能在失去同步后发送 | 上下文结果绑定连接修订；发送前再次检查同步状态；失败的打开允许重试，已发送命令保持原收据或结果未知状态。 |
| 未打开完成的并排会话可能接收主会话事件 | 明确上下文就绪及事件归属，关闭后停止交付。 |
| Web 上下文关闭请求失败会保留本地 socket；撤销与打开并发时遗留上下文 | 本地关闭先完成并保持幂等；撤销先停止会话授权，随后释放已存在或晚到的上下文；关闭上下文的 WebSocket 重连正常拒绝。 |
| 会话行与文件行复制菜单定位逻辑 | 共用 `useRowMenuAnchor`，定位随所属窗口变化。 |
| 生产预览重复递归监听根目录与子目录，停止只取消计时器 | 保留一个递归监听器；停止关闭监听器，构建结束后检查停止状态。 |

| 默认核心名单累加页面布局、图标等细节测试 | 保留测试，移出默认核心名单；本轮仍通过 `--all` 验证。 |
| Runtime 工件能力清单漏掉 9 个电脑工作区能力 | 根据实际 Runtime 声明校正工件清单；加强能力覆盖测试，并比对实际 Runtime 与工件的能力哈希。 |
