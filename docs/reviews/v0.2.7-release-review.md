## 发布基线与范围

- 上一正式版：`v0.2.6`。本次包含 PR [#51](https://github.com/the-snowpear/omp-studio/pull/51) 的性能优化、PR [#52](https://github.com/the-snowpear/omp-studio/pull/52) 的 OMP 19.0.1 适配，以及 `d7649bd` 的 Plan、会话资源和反汇编 UI 改动。
- 桌面版本：`0.2.7`。Runtime：`19.0.1-studio.1`；上游固定提交 `f40f335845f0b136453d12fec8d6057011082766`。
- 根目录和 14 个 workspace 的版本、内部依赖均由脚本精确更新。随后运行 `npm install --package-lock-only`，逐项比较锁文件的全部 `node_modules/` 条目，第三方依赖没有变化。根和 Renderer 的 Mermaid 声明一致。
- `PREVIEW_MODE_SWITCH_ENABLED=false`。发布说明完整列出 Windows x64、Windows ARM64、macOS arm64、Linux x64 的实际安装包名。发布计划为四桌面目标、六 Runtime / SSH 目标。
- Changelog、中文和英文 README、文档索引与 [Release 文案](../releases/v0.2.7.md) 同步。三张截图直接来自本版正式组件，以演示数据展示；图片存放在 `docs/images/releases/` 并固定链接到版本 Tag。
- 根目录原有 0 字节临时文件 `MobileAccessSettings.tsx` 已移至本地忽略的审查目录保留，产品文件仍是 `apps/renderer/src/settings/MobileAccessSettings.tsx`。

## 审查发现与处理

1. 反汇编分页回归仍通过改版前的「IDA 视图」寻找控件，已同步为现有「查看内容」，保留原先对分页绑定地址和版本的行为断言。
2. Markdown 资源预览首次懒加载在并行测试中超过默认一秒查询等待。独立复验通过；该异步可见性断言的等待上限调整为五秒，未更改产品行为。完整 14 套件复验通过。
3. 再生补丁前发现新增接缝文件 `packages/tui/src/html-form/model.ts` 在开发检出里处于未跟踪状态。恢复其 intent-to-add 后重新运行 `omp:patches:regen`，四份补丁、312 个 overlay 和 `series.json` 与已合入版本完全一致。没有发布额外 Runtime 源码变更。
4. 独立 Runtime 验证目录首次缺少原生 addon；补入本机同源构建的 Windows x64 addon 后重跑，类型、源码测试和 CLI smoke 全部通过。未借用上游发布二进制，也没有改动正式签名密钥。

## 界面与验证边界

- Windows x64 / Chrome 的完整工作台中实测了 Plan 草稿实时预览、`zh → en → zh`、收起再打开与保存；会话 Markdown 文件的分栏、语言切换及草稿保留；反汇编输入和界面热切。截图没有经过重绘或生成处理。
- 真实模式断开 Runtime 时，反汇编显示连接空态，没有演示数据库。真实 API 路径的资源分页、草稿、失败回执和会话隔离由对应行为套件覆盖；这不等同于真实 IDA／Ghidra 数据库操作验收。
- 本轮没有执行模型付费请求、Kiro 实际登录、外部 Live 服务、ovnfs 实际挂载、六平台真实 SSH 登录，也未做 macOS Gatekeeper、Windows ARM64 或 Linux 的真机安装验收。跨平台包由发布矩阵进行架构、权限、签名与资产审计。
- 既有 Windows x64 编译 Runtime canary 的身份与冒烟记录见 [OMP 19.0.1 迁移报告](../migrations/omp-19.0.1.md)。性能数字沿用 [实测报告](runtime-performance-2026-11-19.md) 的环境和样本，不扩大为所有设备的性能保证。
