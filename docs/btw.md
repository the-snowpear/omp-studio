# BTW 旁路问答

BTW 围绕当前会话的上下文提问，使用当前模型、思考设置和系统提示。回答流式显示并保存在独立的话题历史中，不写进主对话，也不执行工具。主任务运行时仍可使用 BTW。

本次功能对齐以项目固定的 OMP **18.13.2** 为准。Runtime 直接复用原生 `runBtwTurn`，包括历史重放、图片处理、输出整理和失败后的请求链切换。

## 使用

| 原生能力 | Studio 入口与行为 |
|---|---|
| `/btw 问题`、空 `/btw` | 主输入框与命令面板均新建话题，文本和图片一起传递；空命令打开历史，侧栏支持新建与追问 |
| 文本与图片 | 输入问题，选择、粘贴或拖入图片；粘贴图片文件路径由 Runtime 使用原生路径识别与图片加载器读取 |
| 语音 | 输入框的麦克风，沿用应用的听写配置与按住说话设置；参见[语音输入](dictation.md) |
| 历史与连续追问 | 话题下拉框显示时间、状态和轮数；进程中断与主动中止分别展示。已完成、已中止、失败、进程中断的话题均可追问，图片随历史一起传给模型 |
| 流式输出与后台运行 | 关闭／收起面板不停止回答；重新打开继续查看。查看其他话题时，可用「后台正在回答」返回当前话题；面板隐藏时，完成会提示 |
| 复制 | 复制当前非空回答；当前轮尚无文本时复制前一个非空回答。保留原始空白，部分回答也可复制 |
| 分支 | 当前主会话的单轮、已完成答案可分支，提问图片会一同保留；原会话和分支点必须仍有效，主会话不能正在运行 |
| 子代理 BTW | 从所选子代理的上下文提问，使用相同的输入、历史、图片、语音、复制和中止界面；历史按目标会话隔离，不转发到主 BTW |

多轮话题、历史回放和子代理答案不通过 BTW 分支按钮提升为主会话；这是原生规则。没有独立的 BTW 模型选择器，普通文件路径也不会触发文件读取工具。图片路径以当前连接的 Runtime 文件系统为准；向远端发送本机图片时，请选取、粘贴或拖入图片文件本身。

BTW 绑定当前查看的会话。打开未恢复的历史会话的 BTW 时，先恢复对应 Runtime，再读取历史或提问；不会借用另一个活动会话的上下文。空白会话首次 BTW 会先建立持久会话文件。

历史刷新在空闲时重新读取原生侧文件，可看到同一会话由 CLI/RPC 写入的话题；追问前也重新读取，以保留其他进程的新增回答。问题不再附加 Studio 的 64K 字符限制，仍受传输协议与模型本身的上下文限制。

图片正在加载时按发送，会等待本次附件就绪后只发送一次。取消输入或切换话题后，晚到的图片不会插入另一个草稿；加载失败会显示原因并保留草稿。

## 键盘

| 焦点位置 | 快捷键 |
|---|---|
| 输入框 | Enter 发送；Shift+Enter 换行；Esc 取消本次草稿并回到阅读区 |
| 阅读区 | F / Enter 聚焦输入；C 复制；X 中止；B 分支（可用时）；Esc 收起 BTW |
| 话题下拉框 | 沿用应用选择器的方向键、Enter、Esc；话题较多时可以搜索 |

输入框中的普通字母不会触发阅读快捷键。Studio 保留多行编辑，原生终端的历史追问框是单行输入。

## 版本与验证

新增行为需要使用当前 `omp-patch/overlay/` 与生成补丁构建的 Runtime；只更新 Renderer 或继续运行旧 Runtime 二进制不会更新后端能力。`btw.images.resolve` 通过能力清单协商，旧 Runtime 不启用路径附图。

预览模式的 BTW 问答使用同形本地话题和回答，不发起 Agent 请求。语音输入与主输入框一致：麦克风及选项始终显示，有真实会话时读取真实听写配置并走桌面听写链路；没有会话、桌面通道或可用 Runtime 时说明原因。真实模式读取 Runtime 历史，不回填演示数据。

回归覆盖：失败／中止／中断后追问、长话题、历史图片重放、图片路径解析、带图分支、请求回执乱序、草稿保留、附件等待与话题切换、子代理绑定失效和无主会话回退。
