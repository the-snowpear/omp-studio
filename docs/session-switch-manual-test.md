# 一轮人工会话切换采样（约 1–2 分钟）

你负责正常操作应用，助手负责读取数据。脚本只记录性能数字，不读取或导出会话正文、标题、路径、会话 ID、密钥，也不会主动切换会话或发送命令。

## 开始前

- 这次先按平时的 **`启动预览.cmd`** 重新打开当前代码，复现原来的使用环境；不要用旧安装包，也不要用带演示数据的 `启动预览版.cmd`。若顶栏有演示预览开关，保持关闭。先等已有任务结束，不要为了采样中断正在工作的 Runtime。
- 应用加载完、侧栏可见后，先确认 **Ctrl+Shift+I / F12** 能打开开发者工具，再关闭它；确认后才启动进程采样。只用一个主对话视图，不额外开对话浮窗。
- 保持应用窗口在前台、尺寸不变。不要发送消息、编辑源码、切换主题，也不要特意连接或断开 Runtime。
- 先打开 [采样 Console 脚本](../scripts/manual-session-switch-capture.js)，全文复制好；**不要双击这个 `.js` 文件执行**。

## 操作

### 1. 启动进程采样

双击项目根目录的 **[采集会话切换.cmd](../采集会话切换.cmd)**。

它按程序路径识别 OMP 主进程，并排除 Renderer、GPU 等子进程，不依赖窗口标题或开发者工具是否打开。最多记录 120 秒；通常不用填 PID，找到多个 OMP 实例时才会列出进程让你选。它不会启动、关闭或重启任何应用。

### 2. 开始应用内采样

Windows 的 **`启动预览.cmd` 开发预览**中，先点击 OMP 主界面，再按 **Ctrl+Shift+I** 或 **F12**，会打开独立的开发者工具窗口；切到 **Console** 标签，粘贴刚才复制的脚本并回车。随后在 5 秒内关掉开发者工具，避免它占用额外 Renderer。

旧的 Windows 主进程没有绑定这些快捷键；更新后必须真正退出应用（若留在系统托盘，右键退出），再重新运行 `启动预览.cmd`，只刷新页面不够。打包版不启用这些开发快捷键。不要使用内置 Browser 面板的“开发者工具”，那个 Console 属于网页，不是 OMP 主界面。

从回车时起，大致按这个节奏操作即可：

| 时间 | 操作 |
|---|---|
| 0–15 秒 | 关闭开发者工具，保持应用在前台，先不操作 |
| 15–30 秒 | 在同两个会话 A/B 之间切约 6 次，每次间隔约 2 秒 |
| 30–45 秒 | 依次打开约 6 个不同会话，每次间隔约 2 秒 |
| 45–60 秒 | 不再切换，停在最后一个会话上 |

不用追求秒表级精确。第 60 秒会自动停止应用内录制，并下载一份 `omp-session-manual-*.json`。录制按阶段分成独立的有界记录，避免整轮切换挤掉最初的空闲数据。

### 3. 把文件放到一起

把下载的 JSON 保存或移动到项目的：

```text
outputs/perf/manual-session-switch/
```

进程采样的 `processes-*.jsonl` 已自动写到这个目录。继续让应用保持前台空闲，等采样窗口出现 **Finished**（整套最长约 2 分钟）。

然后告诉助手 **“采完了”**，再补一句这轮有没有明显卡住、当时是在 A/B 切换还是打开不同会话。无需贴对话内容，也不用手动分析文件。

## 如果中途出问题

- **应用卡住或没下载 JSON**：不要反复点击或立即强关。等进程采样结束后告诉助手；独立进程曲线可能仍然有效。
- **想提前导出**：在应用 Console 执行 `window.ompManualSessionCapture.finish()`。
- **想取消、不导出**：执行 `window.ompManualSessionCapture.cancel()`。
- **提示采样 API 不存在**：当前窗口不是本仓库最新构建；先确认启动入口和窗口，不要通过更改安全设置来绕过。
- 不要在采样时刷新页面。离开页面时脚本会取消录制，避免下次启动继续采样。

## 助手会检查什么

- 每次切换后，引擎、Store、挂载文档和脱离页面的 DOM 是否保持有界。
- query / bootstrap 耗时、长任务、定时任务延迟与切换顺序。
- 主进程、Renderer、GPU、网络和 Runtime 各自的私有工作集、工作集、私有提交量与 CPU。
- 切换后的空闲期是否稳定；工作集、JavaScript 堆和 GPU 不会相加冒充一个准确的“总内存”。

当前代码已通过专项回归和可见页面验证，但原问题的实机性能验收仍以这次真实使用数据为准。
