# OMP Studio 0.2.3

0.2.3 给 Linux 客户端补上了应用内差分更新，把指挥台和 Agent 之间的真实消息记录接进了 Agent Hub，重做了右侧 Agent 档案与模型拉取筛选，并集中修掉了一批 0.2.2 反馈的模型读取、配置审批和失效工作区恢复问题。内置 Runtime 升至 **18.20.2-studio.6**。

完整变更记录见 [CHANGELOG](https://github.com/the-snowpear/omp-studio/blob/v0.2.3/CHANGELOG.md)。

Windows 请按设备架构选安装包，安装程序目前尚未经过 Authenticode 签名。macOS 首次安装推荐 DMG；应用仍为 ad hoc 签名，尚未经过 Apple 公证，首次打开被拦截时的处理方法见[入门文档](https://github.com/the-snowpear/omp-studio/blob/v0.2.3/docs/getting-started.md)。

Linux 包面向支持 **AVX2** 的 x64 处理器，构建基线为 Ubuntu 24.04 / glibc 2.39。**0.2.2 的 Linux 用户请手动下载安装一次 0.2.3**，从本版起 AppImage 和 deb 都支持在「设置 → 更新与维护」里直接检查和差分更新了。安装与沙箱要求详见 [Linux 客户端说明](https://github.com/the-snowpear/omp-studio/blob/v0.2.3/docs/linux.md)。

Windows 与 macOS 已有用户可以直接在「设置 → 更新与维护」检查更新，或者下载对应平台的完整安装包覆盖安装。Release 里的 `omp-studio-remote-*` 是 SSH 远端环境包，平时由 Studio 按需部署，不是桌面安装程序。

## Agent Hub 里的指挥台、真实通讯与新版档案

上一版把指挥台做进了工作台侧栏和浮窗，但进到整页的 Agent Hub 时还是老列表，而且「通讯」面板还空着。这一版把两边打通了：

- **默认先看指挥台**：打开 Agent Hub 的「代理」页直接进入「指挥台」名册视图（仍可随时切回「平铺」或「按父代理」）。左边看编队、时间线、星图和通讯，右边看详情，选中项实时同步。
- **Agent 间消息接上真数据**：详情页的「消息」标签按时间列出当前 Agent 发出和收到的消息，包含 `@` 的对象、回复原文和进度标记，点对方名字直接跳过去；指挥台的「通讯」视图和星图连线共用同一份已送达记录，一次广播合并成一条。停驻、已结束的 Agent 以及重启后的历史记录都能查看（需要本版随附的 `18.20.2-studio.6` Runtime；连接旧版 Runtime 会提示「读不到 Agent 间通讯」）。
- **重做右侧 Agent 档案**：头部整合了父代理入口、像素头像、状态、运行时长、模型（回退模型用琥珀色标出）以及按状态裁剪的操作按钮（「打开对话」合并了原来的打开与发消息，「恢复」只在停驻时出现，「释放」只在结束后出现）。概览按当前、任务、用量格与上下文条、谱系、产物与变更分区排布；BTW 直接铺满整个面板。
- **同一张脸走到提交面板**：选择性提交里的参与 Agent 和改动片段归属也换成了同一套像素头像——主代理带皇冠、运行中睁眼，一眼就能认出哪段代码是谁写的。

## 模型拉取筛选与工作台细节

- **端点拉取模型更好挑了**：在模型配置里从供应商接口获取模型列表后，现在可以直接搜索名称或 ID，并按「全部 / 新增 / 待匹配 / 已选」筛选和批量勾选；遇到匹配到多个内置目录项的模型，也能在列表里直接切换目录匹配来补全推荐参数。（注：[#41](https://github.com/the-snowpear/omp-studio/issues/41) 中提到的外部工具配置导入/同步尚未包含在本版中。）
- **空白新对话更干净**：新建但还没发第一条消息的对话继续保持欢迎引导页，默认先收起右侧工具栏，等你点开工具或开始工作时再展开。

## Linux 应用内差分更新

`AppImage` 和 `deb` 现在跟 Windows、macOS 一样支持应用内验签与后台差分下载：

- **AppImage**：确认所在目录当前用户可写即可在后台准备更新，点「重启更新」完成替换；若新版启动失败会尝试恢复旧文件。
- **deb**：后台准备好目标包与可回滚版本后，点「重启更新」会拉起系统图形化 polkit 授权，应用退出后通过 `apt` 完成安装，并避免被外部包操作打断；安装或新版启动失败时同样尝试通过 `apt` 恢复上一版。

## 问题修复

- **配置审批不再批准后超时**：按「允许一次」或「本会话允许」正确绑定确认凭据，修复点批准后提交失败并最终超时的问题（[#32](https://github.com/the-snowpear/omp-studio/issues/32)、[#33](https://github.com/the-snowpear/omp-studio/pull/33)）。
- **模型列表与会话授权对齐**：工作区读取或刷新模型前先连接当前 Runtime；对话模型目录改为从当前会话的 Runtime 读取，解决已配置模型一直显示未验证、列表为空或串用其他会话授权模型的问题（[#33](https://github.com/the-snowpear/omp-studio/pull/33)、[#38](https://github.com/the-snowpear/omp-studio/issues/38)、[#40](https://github.com/the-snowpear/omp-studio/pull/40)）。
- **首次改配置不必手动刷新**：未初始化的客户端在发出第一条命令前先建立事件回执订阅，修复模型配置、子代理开关等改动明明已生效却一直转圈等待的问题（[#36](https://github.com/the-snowpear/omp-studio/issues/36)、[#37](https://github.com/the-snowpear/omp-studio/pull/37)）。
- **失效工作区自动回退与恢复**：启动时遇到已删除或不可用的旧目录会自动回退到有效项目，诊断页也可直接重选目录、新建对话或清理失效记录，清理前备份注册表并完整保留项目文件与历史会话（[#31](https://github.com/the-snowpear/omp-studio/issues/31)、[#39](https://github.com/the-snowpear/omp-studio/pull/39)）。
- **会话标题不再画双份图标**：原生会话标题已经内嵌 emoji 和短码时，不再额外重复绘制一份标签（[#34](https://github.com/the-snowpear/omp-studio/issues/34)、[#35](https://github.com/the-snowpear/omp-studio/pull/35)）。
