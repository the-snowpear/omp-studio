# OMP Studio 0.1.13

本次修复 v0.1.12 在 **Windows 和 macOS** 上启动后显示 **Studio client unavailable**、无法进入工作台的问题，同时减少发布流程中的重复编译。Runtime 继续使用 **OMP 18.12.6 / 18.12.6-studio.9**。

## Changelog

### 修复

- **Windows / macOS 启动失败（[#8](https://github.com/the-snowpear/omp-studio/issues/8)）**：preload 错误导入后台 Host 模块，导致沙箱拒绝加载 Node API，桌面桥接对象未能注入。改为无 Node 依赖的客户端实现，保持 `sandbox` 与 `contextIsolation` 开启。
- **启动回归检查**：生产检查执行实际 preload bundle，分别验证 Windows、macOS 环境中的四个桌面桥接对象、bootstrap 调用和事件过滤；打包阶段拒绝沙箱不支持的外部模块。

### 构建与发布

- Linux、Windows、macOS 的 x64 / ARM64 六种远程环境支持复用已有签名 Runtime，命中后跳过 Bun、Rust 与 Runtime 编译。
- 远程任务跳过 Renderer 构建、Electron 二进制下载与重复桌面编译；已复用 Runtime 不重复上传，发行工件上传减少额外压缩。
- 旧缓存迁移会核对 Runtime 源码与公钥，沿用相同版本的原签名字节。Runtime 源码改变或缓存缺失时仍需冷构建，实际耗时以 Actions 为准。

桌面安装包为上表三种平台；六种 SSH 远程环境包继续随 Release 提供。Runtime 与更新清单继续使用既有 Ed25519 发布密钥验证。
