# OMP Studio 0.2.2

这一版把 Linux 桌面安装包补上了，也给 SSH 工作区加了 tmux。项目外的文件现在可以直接在 Studio 里浏览；Agent 面板换了新样子，内置 Runtime 从 OMP 18.18.0 升级到了 **18.20.2-studio.5**。

这次改动不少，下面挑几个用得上的说。完整记录在 [CHANGELOG](https://github.com/the-snowpear/omp-studio/blob/v0.2.2/CHANGELOG.md)。

| Windows ARM64 | [下载 Setup](https://github.com/the-snowpear/omp-studio/releases/download/v0.2.2/OMP-Studio-Setup-0.2.2-windows-arm64.exe) |

| Linux x64 | [下载 deb](https://github.com/the-snowpear/omp-studio/releases/download/v0.2.2/OMP-Studio-0.2.2-linux-x64.deb) · [下载 AppImage](https://github.com/the-snowpear/omp-studio/releases/download/v0.2.2/OMP-Studio-0.2.2-linux-x64.AppImage) |

Windows 按设备架构选安装包，安装程序目前尚未经过 Authenticode 签名。macOS 首次安装推荐 DMG；应用仍为 ad hoc 签名，尚未经过 Apple 公证，首次打开的方法见[入门文档](https://github.com/the-snowpear/omp-studio/blob/v0.2.2/docs/getting-started.md)。

Linux 包面向支持 **AVX2** 的 x64 处理器，构建基线为 Ubuntu 24.04 / glibc 2.39。Ubuntu、Debian 用户可以优先尝试 deb；AppImage 需要 FUSE 2 和可用的用户命名空间。Linux 桌面版本目前需要手动下载升级，Runtime 仍可在应用内更新。安装和系统要求详见 [Linux 客户端说明](https://github.com/the-snowpear/omp-studio/blob/v0.2.2/docs/linux.md)。

已有用户可以在「设置 → 更新与维护」检查更新，或者使用对应平台的完整安装包。Release 里的 `omp-studio-remote-*` 是 SSH 远端环境包，平时由 Studio 按需部署，不是桌面安装程序。

## 文件浏览器：不用先把文件放进项目

以前想在工作台里打开项目目录以外的文件，往往还得回到系统文件管理器。现在可以从「添加工具」打开文件浏览器：本机会显示本机文件，SSH 对话会显示对应远端机器上的文件。

你可以在树、列表和分栏视图间切换，固定常用文件夹，直接打开、编辑文件，或把文件引用加进对话。新建文件夹、重命名和设为项目在本机及 SSH 下都可用；系统打开方式和回收站操作仅支持本机。具体用法见[文件浏览器说明](https://github.com/the-snowpear/omp-studio/blob/v0.2.2/docs/file-browser.md)。

## SSH 终端可以附加 tmux 了

在 SSH 工作区的终端里点击「附加 tmux…」，就能选择已有会话，或新建一个会话。tmux 窗口会出现在终端标签里，分屏按远端布局显示，也可以在界面里拆分、缩放和调整大小。

退出 Studio 或 SSH 断开时只会分离连接，远端会话和进程继续运行；下次可以重新附加。这个功能需要远端安装 **tmux 3.2 或更高版本**，目前只支持 SSH 工作区，不接管本机终端里手动启动的 tmux。更多用法和限制见 [tmux 说明](https://github.com/the-snowpear/omp-studio/blob/v0.2.2/docs/tmux.md)。

## Agent 多起来时，也能看清谁在做什么

把 Agents 面板放到侧栏、底栏或浮窗，就会看到新的 Agent 指挥台。编队视图按派生关系列出 Agent；时间线能回看本次运行中记录的状态变化；星图则把层级关系画在一起。点选 Agent 可以查看任务和用量、打开它的对话或发起 BTW。

时间线只能回看本次运行中记录到的状态和用量，没有记录的部分会留空。通讯视图目前还是预留位置：Runtime 暂未向 Studio 提供 Agent 之间的消息记录。

## Runtime 和工作台的其他变化

- **选择性提交**：可以先查看本次准备提交的文件和改动，再选择并确认，不用盲着提交。已有的普通 Git 提交方式继续可用。
- **输入历史**：可以搜索、查看和复用之前输入的内容；选择一条后只会放回输入框，不会自动发送。
- **Agent 表单与任务**：提问支持题组、图片、「其他」和选项附注；Agent Hub 可以创建分步任务，并查看各组进度。
- **模型与账户**：可用模型以当前 Runtime 的结果为准；模型角色可以关联和编辑系统模板，账户页面会显示服务返回的用量，未提供的数据保持未知。
- **浏览器与 GitHub Actions**：内置浏览器可以新开原生页面并查看 Console、Network 和下载；Actions 按运行、作业和步骤展开，失败时可查看日志。
- **英文与外观**：补齐了多处英文界面和运行时语言同步；新增关闭、柔和、标准、绚丽四档光效，不喜欢也可以关掉。

## 修了一些容易碰到的问题

- 恢复历史会话时，如果原来的目录已经不存在，可以选择已有工作区继续；启动失败时会保留原来的活动工作区。
- 粘贴带图片的富文本时，图片读取不会打乱插入位置；SVG 和嵌套表格也能正确处理。
- Bash 审批规则编辑会保留项目和路径作用域；选择性提交的预览不会被迟到的旧结果覆盖。
- 手动检查更新失败时会显示原因，不再只凭本地状态说「已经是最新」；Worktree 创建成功但打开失败后，可以在当前会话视图中重试打开已创建的目录。
- 对话浮窗拖过项目列表时，不再误判为停靠到侧栏；普通终端识别到 `tmux -CC` 控制序列时也不会一直缓冲。
