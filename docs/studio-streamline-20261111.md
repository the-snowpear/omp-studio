基线：`be2673b`。独立工作树分支：`codex/studio-streamline`，目录 `D:\Project\.worktrees\omp-studio-streamline`。用户明确要求本次不另做备份；原工作树保留不动。

## 已确认的边界

- 保留功能、界面入口、协议、持久化格式，以及真实／预览两条路径。
- 保留已合入的会话切换共享读取、归档 Worker、缓存预算和竞态修复。
- 隐藏闲置网页只节流，保护实际操作、加载、下载、音视频及 DevTools；不自动卸载或关闭。
- 复用现有 Dock 稳定宿主、延迟面板、Store 和检查入口，不增加通用框架或第二套缓存。
- 各阶段独立提交，测量没有通过或没有执行的项目单独记录。

1. 生产构建、首屏资源、原生启动与会话切换基线。

## 测量方法

`node scripts/renderer-assets.mjs apps/renderer/dist outputs/streamline/<阶段>/assets.json` 统计生产入口的静态 JS 依赖、首屏 CSS 与完整 Renderer 目录。静态依赖去重；启动中实际触发的 lazy 资源另由原生测量记录。gzip 只用于字节对比，不代表本地文件读取量。

启动复用 `startup-perf.mjs` 的合成工作台，并与真实 Host 的 `native-session-perf.mjs` 分开记录。Windows 原生浏览器检查使用隔离配置和本地 HTTP fixture，不发送模型请求或使用用户会话。

## 结果

### 首批加载精简

Git、上下文查看器、Computer 正文复用 Dock 首次可见才挂载的机制；本地资源编辑器只在对话框打开时加载，具备局部失败重试。模型配置页样式随该页面加载；Composer／Git 复用的菜单与徽章规则抽到常驻 `model-picker.css`，所有 harness 同步移除页面提前导入，避免测试入口与产品入口采用不同加载策略。

| 实际生产入口 | 基线 | 最终加载修改 | 变化 |
| --- | ---: | ---: | ---: |
| 静态 JS，raw bytes | 4,391,054 | 3,213,914 | −26.8% |
| 首屏 CSS，raw bytes | 764,829 | 655,911 | −14.2% |

CodeMirror 及语言目录不再出现在首屏静态依赖中。以上不是启动时间或完整安装包的缩减比例。原始记录位于 `outputs/streamline/{baseline,final}/assets.json`。

`npm run check -- --only renderer --suite DeferredPanel --suite App --suite ModelConfigPage` 通过；Renderer 生产构建通过。基线合成工作台五次采样完成，其启动时间包含自动化启动成本，最终性能结论等待同条件对照。

### 托管网页活动

`BrowserPageActivity` 归每个实际网页实例所有。可见窗口、加载、媒体、声音、DevTools、元素选择和在途操作阻止节流；最后一个保护结束后等待 30 秒。普通目录读取不续期。隐藏只降低调度，不导航、不销毁页面；真正关闭时清理计时器和窗口监听。所有 CDP 请求、attach 和截图都有活动生命周期，下载在完成／取消后释放保护。

Electron 原生实验确认，单独设置后台节流不会立即更新停放页面的可见性。切换时通过一次原生 capture 同步可见性；Agent 的焦点模拟也随睡眠暂停、唤醒恢复。没有增加常驻轮询。

- 单元回归覆盖 30 秒宽限期、所有保护条件、重复状态通知、重叠请求和退出清理。
- 隔离原生页面：同一 1.2 秒采样窗口，动画 292 → 0 帧、10 ms 计时器 121 → 1 次。页面 ID、表单和 JavaScript 状态保留；35 秒 Agent 请求、错误清理、媒体、下载、最小化截图和恢复通过。这个数字属于受控 fixture，不是所有网站的 CPU 节省比例。
- 真实 Runtime relay 验收覆盖正常／隔离子 Agent、接管、下载、Runtime 代次切换、关闭和重启；基线与当前代码各自使用全新配置完成完整流程。
- 原冒烟夹具缺少当前 Runtime 的 SessionManager 身份、view-session 能力和 Eval owner；补齐后保持所有原断言。重启夹具还漏了首次进程已有的宿主 `about:blank` 初始化；基线同样超时，补齐初始化后通过，没有放宽超时或产品检查。

证据：`outputs/streamline/browser/{baseline-full,current-full}.json`、`native-*/report.json` 与对应日志。失败实验保留原文件。

长稳初次运行分别在第 10／162 次循环的新建后台页上超时；后续短复测还遇到 Windows 显示表面不可用，基线管理器同样无法截图。两次加载超时的诊断中页面尚未进入首个文档；一次记录到整机可用内存仅约 338 MiB，期间也观察到约 65 MiB 的低点。不能将这些运行记为通过，也不能仅凭资源压力断言不存在产品问题。

收敛首次创建路径：新页面沿用原有的 awake 初始状态，只有真实节流状态切换才做可见性同步，避免在初始空白文档上多做截图。最终原生流程和 60 次新建／关闭检查通过，每次回到 1 个页面；最终两小时测试另行运行。测试先通过已有截图入口建立一个真实绘制帧，再采样动画；所有加载超时和节流阈值保持原样，失败时保存页面状态、事件与可用内存。

### 职责拆分

App 入口由约 9,600 行收敛为 255 行，只负责连接、订阅和组合。侧栏／文件树、菜单／顶栏、底栏布局分别归自己的组件；Git 面板的打开意图移入 Git 装配组件，分支创建／排队切换移入对应 hook。文件系统菜单动作和会话重命名分别拥有自己的异步状态。保留现有 Composer 草稿、会话选择、共享读取与稳定宿主，没有第二套状态容器。

模型配置的草稿转换、命令收据、排序、Provider 发现与参数编辑拆入 `models/config/`，页面约 2,247 行；Agent Hub 的投影、能力、导航、卡片、详情和作业行拆入 `agents/hub/`，页面约 1,840 行。工作台外壳和对话正文装配仍分别约 2,800／2,950 行：它们保留跨功能协调，没有用行数门槛把同一作用域机械分散。

完整 `npm run check -- --production` 通过，含核心 Renderer、Host、Desktop、协议、preload 与远端 Host 构建。独立 Electron 的会话切换冒烟使用 16 个合成会话，49 个采样点、页面错误 0，阅读锚点恢复通过；这是行为回归，不是新的会话切换提速结论。

生产流式门禁五次采样通过，包含长历史、展开位置、会话淡入、工具移交不重挂载。真实／预览 App、模型配置、Agent Hub、Dock／Workspace 定向回归通过。界面验证确认未使用重模块在启动时没有请求；打开模型配置才加载 CodeMirror，返回工作台仍保留输入草稿。独立模型菜单 fixture 在未加载模型页 CSS 的情况下具有正确的分组、定位和徽章样式。截图与资源清单在 `output/playwright/streamline/`。

本机仅验收 Windows x64。macOS Apple Silicon 的原生窗口、节流和发行物仍需对应设备验证；本轮没有签名、发布、安装覆盖或更新用户数据。

Renderer 全量首轮为 269 个文件通过、1 个失败：旧测试要求折叠历史 Context 立即读取统计，与基线已合入的延迟读取规则相冲突。测试更新为折叠不读、首次展开读取一次、收起再开复用结果；产品实现未改。高负载重跑出现额外超时和测试释放后异步写入，补齐 `multiAgentDock` 自建 Store 的 dispose 后，采用相同断言与超时、单个 worker 跑完 **270 个文件／1,889 项测试，全部通过**。机器资源压力下的失败日志保留，未把这些失败运行算入性能样本。

### 首次打开面板回退与修复

初次交替测量发现，把 Git 改为 `React.lazy` 后首次打开中位数约 53 → 349 ms，未达到方案的无回退要求。现有 `lazyPanel` 改为首次挂载后请求模块，在模块就绪时更新本地组件状态，避免抛出 Promise 触发 Suspense 的额外重试等待。每个模块仍共享在途请求和成功结果；隐藏不重挂载，卸载不回写，失败保留局部重试，渲染错误仍由原 ErrorBoundary 处理。

修复后按 A/B、B/A 顺序各 5 次打开模型配置、Agent Hub 和 Git。点击到正文提交并经过两帧的中位数如下，包含现有页面切换动画：

| 模型配置 | 843.8 ms | 345.6 ms |
| Agent Hub | 840.6 ms | 341.1 ms |
