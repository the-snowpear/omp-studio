## 2. 产品目标与边界

### 2.1 五类可放置位置

| 位置 | 产品名称建议 | 展示方式 | 结构限制 |
|---|---|---|---|
| 左侧栏 | 左侧栏 | 固定导航＋纵向工具卡片 | 导航固定在上，工具卡片可排序 |
| 对话区右侧 | 对话工具区 | 完整卡片列／悬浮图标／隐藏 | 多张纵向卡片，不做嵌套标签组 |
| 最右侧栏 | 右侧栏 | 浏览器式标签组 | 最多上下两组 |
| 底部 | 底栏 | 浏览器式标签组 | 最多左右两组 |
| 应用内悬空 | 浮窗 | 单模块或多标签组 | 浮窗内部不再分割 |

对话区、Composer、应用标题栏和全局导航结构不参与拖动。

项目／会话导航固定在左侧。允许整体收起左侧栏，但不能把项目／会话导航拖入其他区域。

### 2.2 首版模块目录

| 模块 ID | 内容 | 默认位置 |
|---|---|---|
| `files` | 工作区文件树及其现有操作 | 左侧卡片区 |
| `changes` | 会话文件变更 | 右侧标签组 |
| `git` | Git 与现有 worktree 入口 | 右侧标签组 |
| `browser` | 浏览器观察与控制 | 右侧标签组 |
| `computer` | Computer 观察与控制 | 右侧标签组 |
| `agents` | 当前侧栏中的子代理 roster | 对话工具区 |
| `terminal` | 现有终端模块及 Shell 列表 | 底栏标签组 |
| `problems` | Problems | 底栏标签组 |
| `tests` | Tests | 底栏标签组 |
| `output` | Output | 底栏标签组 |
| `logs` | OMP Logs | 底栏标签组 |
| `pvlogs` | Preview Logs | 底栏标签组 |
| `btw` | 当前 BTW 会话界面 | 初始隐藏，首次打开浮动 |

所有工具模块都允许放到五种位置，不采用旧文档中的大面板落点限制。

每种模块首版只有一个实例。移动 Terminal 指整个终端模块，内部不同 Shell 不单独停靠；Agents 和 Git 同理。

### 2.3 明确不做

- 独立系统窗口、跨 Electron 窗口拖动、多屏弹出。
- 任意嵌套分割、第三个右侧／底部标签组。
- 同一模块的多份副本。
- 单独拖出某个 Shell、Agent 或 Git 子页。
- 预设 JSON 导入／导出、跨设备布局同步。
- 新增 Environment、Context、Outputs 等信息卡片。
- 将布局保存理解为保存或重启业务任务。

后续新增卡片应通过注册表接入，不能再次修改一套集中式面板分发逻辑。

## 3. 默认布局与视觉规则

### 3.1 默认布局

- 左侧栏展开，沿用当前初始宽度及导航／文件树分配比例。
- Files 显示为左侧导航下方的卡片。
- 对话工具区预放 Agents，但**完全隐藏，连小图标也不显示**。
- 右侧一组：Changes、Git、Browser、Computer；默认收起，默认激活 Changes。
- 底部一组：Terminal、Problems、Tests、Output、Logs、PvLogs；默认标签条可见、正文折叠，沿用当前 Logs 激活项。
- BTW 隐藏，无其他浮窗。
- 新会话继承布局关闭。
- 按会话自动保存布局开启，作为本功能基础行为。

### 3.2 全应用标签视觉

图 1 是形状、层级和选中状态的参考，不要求改变整个产品的主题色。

统一范围：

- 工作台工具标签。
- 设置与功能页面内容标签。
- Agent Hub、模型配置、能力页面、Skills 等实际标签切换器。

不把普通按钮、导航链接和筛选器强行改成工作台标签，也不赋予页面标签拖动能力。

具体规则：

- 圆角矩形，标准工作台标签高度 32px，圆角优先复用约 9px 的现有 token。
- 激活项：面底、细边框、清晰文字；取消下划线式激活表达。
- 非激活项：低强调；悬停与键盘焦点状态清晰。
- 保留已有紧凑字段控件的尺寸，不把所有 `role="tab"` 统一拉到 32px。
- 长标题省略，并通过现有 Tip 系统显示完整名称。
- 标签不换行；溢出时横向滚动，另有“全部标签”入口。
- 激活项切换后自动滚入可见范围。
- 关闭按钮预留宽度，悬停或激活时出现，避免标签文字跳动。
- 不允许标题文字裁切导致关闭按钮不可达。
- 亮／暗主题、compact／standard／cozy 密度都要检查。
- 减少动画模式下关闭非必要过渡。

已有滑动选中镜像若不再参与绘制，应同步移除无用测量和镜像渲染逻辑；不要长期保留一套不可见但仍持续运行的动画系统。

### 3.3 卡片外观与操作

卡片结构为：标题行、可折叠正文、可选调高边缘。

标题行包含：

- 展开／折叠箭头。
- 模块图标及名称。
- 必要的状态摘要或数量。
- 悬停／键盘聚焦时出现的拖动握柄。
- 更多操作菜单。

点击标题非操作按钮区域切换折叠；超过拖动阈值后不再触发点击折叠。

卡片高度规则：

- 短内容按内容自然撑高。
- 长内容使用默认高度上限并内部滚动。
- Browser、Computer 等画面模块初始正文高度 320px。
- Terminal 正文最小高度 240px。
- 用户拖卡片底边后采用手动高度，并提供“恢复自动高度”操作。
- 从卡片区移走再移回，恢复该模块以前的卡片高度和折叠偏好。
- 整列可滚动，卡片内部滚动到边界后允许滚动链交给外层。
- 卡片标题随整列正常滚动，首版不增加叠层复杂的多重吸顶。

左侧固定导航与卡片区分别滚动；分隔线保留比例调节。所有工具卡片移走后，导航使用剩余空间，不保留大片无用途空白。

## 4. 对话工具区与响应式行为

### 4.1 三种状态

对话工具区使用独立于右侧标签栏的状态：

1. `hidden`：完全隐藏。
2. `expanded`：完整卡片列，占据布局宽度。
3. `compact`：图标轨道悬浮在对话右侧，不占布局宽度。

保存用户选择的模式，同时记录最近一次非隐藏模式。默认隐藏，首次显示优先使用完整列；空间不足时呈现紧凑模式。

顶栏提供显示按钮，控制隐藏／恢复；区域内部提供完整列／图标模式切换。两类动作不能混为一个含义不明的循环按钮。

### 4.2 完整卡片列

- 位于对话与右侧标签栏之间。
- 初始宽度 320px，用户可调范围 280–480px。
- 右侧标签栏可同时打开。
- 只有此状态占用横向布局空间。
- 展开或缩放会调用现有对话 reflow 流程，保持阅读锚点。
- 区域为空时显示简洁的“添加工具”入口，允许拖入工具。

### 4.3 紧凑图标轨道

这是用户明确要求的覆盖模式：

- 图标轨道悬在对话内容右侧，允许与内容重叠。
- 不从对话可用宽度中扣除图标栏宽度。
- 位置跟随对话右边界，不能误固定在应用最右侧。
- 显示范围位于对话顶栏下方、Composer 上方。
- 图标顺序与卡片顺序一致。
- 图标过多时允许滚动；名称通过提示显示。
- 模块状态以小型状态点或数量表示，不在图标轨道堆放长文字。

点击图标：

- 只打开该模块。
- 向左覆盖展开，不挤压正文或 Composer。
- 点击其他图标切换模块。
- 再次点击当前图标、点击外部或 Esc 收起。
- 模块自身弹出的菜单、下拉框和对话框不算“点击外部”。
- 覆盖面板使用保存的卡片区宽度，并夹取到当前对话区域可用范围。
- 覆盖层是非模态工具面板，不把整个对话设为不可交互。
- 收起后焦点返回来源图标。

覆盖层是否暂时打开属于瞬时 UI 状态；重启或切回会话时不自动弹出覆盖层。

### 4.4 空间不足时的优先级

继续由现有 `fitWorkbench` 统一计算有效布局：

1. 根据现有规则计算左栏、右栏和对话的可用空间。
2. 完整卡片列能满足宽度预算时保留。
3. 完整列不足以容纳时，临时转成覆盖图标模式。
4. 图标模式不占宽度，左右栏退让沿用原有规则。
5. 放宽后满足恢复缓冲条件，再恢复用户首选完整列。

卡片区隐藏或紧凑时，原有布局回归应保持成立，包括 560px 对话宽度预算和原来的窄窗抽屉行为。

自动紧凑、临时抽屉、窗口缩小后的夹取、暂时不可同时显示的分组，均属于有效布局，不得覆盖用户保存的偏好。

## 5. 拖动、停靠与分组协议

### 5.1 拖动来源

| 来源 | 拖动对象 |
|---|---|
| 模块标签 | 单个模块 |
| 卡片标题非按钮区域或握柄 | 单个模块 |
| 标签组专用握柄 | 整组模块 |
| 浮窗标题栏 | 整个浮窗组 |
| 紧凑图标 | 对应单模块 |

内容区的文本选择、终端输入、文件拖动、图片交互不触发停靠拖动。

### 5.2 手势生命周期

- 左键按下记录起点和来源。
- 位移达到 6px 后进入拖动态。
- 拖动态显示轻量预览和单个有效落点。
- 普通悬停不修改布局树，不反复展开真实区域。
- 松手后一次性提交布局和撤销记录。
- 取消时恢复原状态，不产生存储写入。
- 忽略拖动后残留的 click，避免意外激活或折叠。

取消条件包括 Esc、`pointercancel`、窗口失焦，以及在应用外松手。

### 5.3 落点解释

| 落点 | 操作 |
|---|---|
| 标签之间 | 插入或重排 |
| 标签组正文中央 | 合入该组并激活 |
| 右栏上／下边缘 | 创建或选择上／下组 |
| 底栏左／右边缘 | 创建或选择左／右组 |
| 卡片前后间隙 | 插入卡片顺序 |
| 卡片正文上／下半区 | 插入该卡片之前／之后 |
| 浮窗标签区或正文中央 | 合入该浮窗组 |
| 工作台内无停靠目标的空白位置 | 浮动 |
| 隐藏区域的具名入口 | 放入对应区域并显示 |

边缘分组命中带初始 24px。已有两组时不展示创建第三组的落点。

同时只显示一个候选落点，优先当前最上层容器；容器内部按“标签插入→分组边缘→正文合并”解释。

高亮不仅改变颜色，还显示操作说明，例如：

- “加入右侧下方标签组”
- “插入 Files 下方”
- “移入对话工具区”
- “拆为 3 张卡片”
- “作为浮窗”

对话工具区和最右侧栏必须使用不同名称，不能都只标“右侧”。

### 5.4 分组规则

- 右侧最多上下两组，底栏最多左右两组。
- 新建第二组默认均分空间。
- 分隔线调整比例，支持键盘方向键和双击恢复均分。
- 整组拖入卡片区时按原标签顺序展开为独立卡片。
- 整组拖入标签组时保留内部顺序，目标已有标签保持其相对顺序。
- 移走最后一个标签后删除空组；剩余一组占满区域。
- 卡片区不接受嵌套标签组。
- 槽位空间暂时不足以展示两组时，使用组切换入口临时呈现单组；保存的两组结构不改变。

### 5.5 吸附、锁定与自动滚动

- 吸附默认开启。
- Windows 按住 Ctrl、macOS 按住 Command 暂停停靠吸附。
- 修饰键按下／释放后立即更新高亮，不要求重新拖动。
- Esc 始终取消，不作为“浮动放置”。
- 禁用吸附后松手，在有效工作台范围内形成浮窗。
- 锁定布局阻止拖动、分组及尺寸调整，仍允许切标签、折叠、隐藏、找回及显式应用预设。
- 长卡片列和溢出标签条支持边缘自动滚动；离开边缘或结束拖动立即停止。
- 指针轨迹和预览位置按动画帧更新，不进入整个 App 的高频 React 状态。

## 6. 浮窗与业务生命周期

### 6.1 浮窗能力

每个浮窗包含：

- 可拖动标题栏。
- 一个或多个标签。
- 最小化、最大化／还原、隐藏整组按钮。
- 四边及四角缩放手柄。
- 整组更多菜单。

几何相对于工作台可用区域保存。浮窗不能进入应用系统标题栏，不得遮挡菜单和模态框。

普通浮窗初始最小宽度 320px、最小总高度 200px；Terminal 的最小正文高度仍为 240px。窗口本身更小时，临时有效尺寸可小于首选最小值，但标题栏和恢复操作必须可达。

最大化只覆盖工作台可用区域，保留还原前矩形；不修改系统窗口最大化状态。

### 6.2 最小化胶囊

- 所有浮窗采用统一胶囊形式，包括 BTW。
- 显示当前模块／组名称、必要的运行状态和组内数量。
- 默认排列在对话底部、Composer 上方。
- 多个胶囊自动顺序排列和避让，不能重叠在同一点。
- 空间不足时使用可访问的溢出入口。
- 点击恢复原浮窗与原激活标签。
- 最小化不销毁内容，不终止任务。

### 6.3 隐藏不等于销毁

以下操作只影响显示：

- 切换标签。
- 折叠卡片。
- 隐藏区域。
- 隐藏单模块或整组。
- 最小化浮窗。
- 切换布局预设。

Terminal、Agent、BTW 的任务生命周期仍由各自业务控制。只有用户在业务界面执行“结束终端”等操作才结束资源。

Browser／Computer 特殊处理：

- 仓库中的浏览器是观察流，不是 iframe。
- 模块移动后仍可见时，不能因中间布局状态触发停止观察。
- 真正隐藏、折叠或被其他标签替代时，遵循现有释放观察／人工接管规则。
- 再次显示不擅自恢复人工接管。

### 6.4 找回模块

统一 `openPanel(panelId)` 行为：

1. 已可见：激活并定位。
2. 所属区域隐藏：显示区域并激活。
3. 卡片折叠：展开并滚动至可见。
4. 所属浮窗最小化：恢复浮窗。
5. 模块隐藏：恢复上次位置。
6. 原组不存在：加入原区域现有组；区域为空则重建组。

现有“打开 Git”“打开终端”“查看 Changes”等入口全部改走这一行为，不能把模块强制移回默认区域。

## 7. 布局模型与组件架构

### 7.1 内部类型

新增 Renderer 内部类型，不修改公共 Host 协议：

| 类型 | 职责 |
|---|---|
| `PanelId` | 工具模块稳定身份 |
| `DockRegionId` | `left`、`rail`、`right`、`bottom` |
| `DockGroupId` | 标签组和浮窗组的稳定身份 |
| `PanelDefinition` | 标题、图标、默认位置、尺寸策略、渲染入口 |
| `DockLayout` | 可序列化的首选布局 |
| `DockPreferences` | 吸附、锁定、默认预设、项目继承偏好 |
| `DockAction` | 布局修改语义动作 |
| `EffectiveDockLayout` | 当前窗口计算出的可见区域及几何 |
| `PanelVisibility` | 实际显示状态与可用尺寸 |

`DockLayout` 至少保存：

- schema 版本。
- 左侧卡片顺序及导航／卡片区比例。
- 对话工具区首选模式、最近非隐藏模式、宽度与卡片顺序。
- 右／底区域显示状态、尺寸、标签组、组比例和激活标签。
- 浮窗组、首选矩形、层次顺序、最小化／最大化状态。
- 隐藏模块及其上次位置。
- 每个模块的卡片折叠状态、自动／手动高度。
- 当前基准预设 ID。

只保存结构、ID、数值与偏好，不保存 React 节点、DOM、客户端实例或业务数据。

### 7.2 模型约束

正常动作由 reducer 保证：

- 一个模块恰好属于一个区域／浮窗或隐藏记录。
- 导航不属于可移动模块。
- 右侧、底部各最多两组。
- 激活标签必须属于对应组。
- 空组在用户动作完成后清理。
- 整组移动保持内部顺序。
- 布局锁定时不接受结构与尺寸编辑。
- 应用预设和重置属于显式操作，不被锁定误阻止。

只在读取外部持久化数据时做一次版本兼容和必要归一化，不在组件、Context 和 reducer 周围重复校验。

### 7.3 推荐模块边界

- `dock/`：纯模型、持久化、Context、区域壳、拖动、浮层、菜单与设置。
- `panels/`：把当前 App 中的工具内容接入注册表的薄适配层。
- 现有 `git/`、`browser/`、Terminal、BTW 业务组件继续留在原位置。

`dock` 引擎不依赖具体业务面板实现。注册表在组合层提供渲染入口。

不能为了拆分而把整个 App 闭包传给每个模块。按实际需要提供依赖，并保持稳定回调和引用。

### 7.4 常驻内容宿主

槽位负责壳和占位，模块正文放在稳定宿主中：

- 首次实际显示时挂载。
- 移动、切标签、折叠、隐藏后保持同一个宿主身份。
- 不随区域变化更换 React key 或 Portal target。
- 不用重新挂载实现“移到另一个位置”。
- 隐藏正文通过可见性和 `inert` 管理。
- 终端适配有效尺寸变化，避免零尺寸中间态触发错误 fit。

卡片列滚动时，内容宿主必须同步占位位置和裁剪范围。绝对定位正文不能穿出区域、覆盖卡片标题或截获其他区域的鼠标事件。

几何读取集中在同一动画帧，先读后写；不要为每个模块建立互相触发的测量循环。

### 7.5 可见性、焦点和重绘

- 实际可见性由布局系统统一派生，业务面板不再依赖旧 `sideTab`／`bottomTab`。
- 拖动预览不让业务面板经历一次假隐藏。
- 几何变化只更新布局层，不把逐帧指针位置传进对话树。
- 改变对话宽高时调用现有 reflow 钩子。
- 纯覆盖展开和浮窗移动不改变对话预算。
- 隐藏内容不可 Tab 聚焦。
- F6／Shift+F6 按视觉区域顺序移动焦点。
- 固定宿主的 DOM 顺序不能导致键盘遍历与视觉顺序明显错乱。
- 普通浮窗不设置全局焦点陷阱；模态框沿用现有模态机制。

不为每个历史会话保留一套隐藏模块树；历史会话只保存布局快照。

## 8. 会话保存、预设与迁移

### 8.1 保存身份

布局键包含稳定的连接／执行目标身份、项目身份和会话身份。

不能使用：

- 会话标题。
- 当前页面显示名称。
- 会变化的 Runtime epoch。
- 切换过程中可能滞后的 Runtime snapshot.sessionId。

作用域从用户当前选择目标派生。会话创建完成与切换完成时，明确提交新身份。

### 8.2 新旧会话规则

| 情形 | 布局来源 |
|---|---|
| 已有会话有保存记录 | 自己的布局 |
| 已有会话无记录 | 当前默认预设 |
| 新建会话，继承关闭 | 当前默认预设 |
| 新建会话，继承开启 | 同项目最近使用布局的副本 |
| 分支会话 | 按新会话规则 |
| 归档后重新打开 | 原会话布局 |
| 新建草稿尚无 sessionId | 独立草稿布局，创建后交给新会话 |

新会话继承是“复制起点”，不是共享引用。修改一个会话不会改变其他会话。

项目最近布局只在真实会话布局提交后更新，不由预览模式、窗口自动退让或设置页浏览更新。

### 8.3 保存时机

- 拖放、尺寸拖动结束后保存。
- 模块隐藏、重开、卡片折叠、标签激活等离散操作保存。
- 不在每个指针移动事件写 localStorage。
- 切换作用域前提交当前会话未落盘布局。
- 新作用域恢复期间不能把旧布局误写到新会话。
- 自动夹取、窄窗紧凑和抽屉状态不写回首选布局。
- 会话删除成功后删除对应布局；删除失败保留。
- 归档不删除布局。

存储失败时本次内存布局仍可用；不得因此白屏或反复重置。无需增加多层重试机制。

### 8.4 预设体系

全应用共享预设库，默认选择按以下优先级：

`项目默认预设 → 应用默认预设 → 内置默认`

内置预设：

- **默认：**本文默认布局。
- **专注：**对话居中，隐藏左右工具、对话工具区、底栏和浮窗。
- **调试：**Files 左侧；Git／Changes 右侧上下两组；Terminal／Logs 底部左右两组；Agents 紧凑图标。

预设操作：

- 另存为、更新、重命名、删除自定义预设。
- 内置预设不可覆盖或删除。
- 应用到当前会话。
- 单独设为项目默认或应用默认。
- 恢复当前预设。
- 恢复出厂布局。

预设是布局模板，不含会话绑定、项目路径或运行资源。

用户修改基于预设的布局后显示“已修改”；不会自动更新预设。预设删除后，已有会话布局仍保留；默认引用回退到内置默认。

### 8.5 布局撤销／重做

- 独立保存当前会话最近 20 次布局编辑。
- 包括移动、分组、调尺寸、隐藏／重开、预设应用和重置。
- 不把普通标签浏览和焦点切换作为撤销步骤。
- 不占用编辑器／终端的 Ctrl+Z。
- 首版撤销历史只保留在本次运行内，不持久化。
- 切换会话时不能把 A 的撤销操作应用到 B。
- 重置和预设应用通过布局撤销恢复，不为普通布局操作反复弹确认。

### 8.6 旧布局迁移

读取现有 `LayoutMemory`，把全局和项目布局转换成带来源名称的自定义“旧布局”预设。

- 保留旧宽度、展开状态、选中标签、分隔比例和 BTW 几何。
- 一次迁移，不重复生成预设。
- 旧键保留，新系统不再写旧字段。
- 新会话和无新记录的旧会话使用新默认，不自动套用旧预设。
- 旧项目布局的来源只体现在名称／说明中，不把项目业务身份绑定到模板内容。
- 对损坏或无法迁移的旧记录跳过并使用默认，不扩展为复杂修复框架。

## 10. 预览、平台和性能要求

### 10.1 预览模式

- 预览与真实布局状态隔离。
- 预览拖动和预设演示只影响演示状态。
- 演示操作不覆盖真实会话布局、项目默认或用户预设。
- 真实工具仍使用已有真实数据源。
- 终端保持本机真实 Shell；不能换成假终端。
- 预览模式既有真实写表面按项目约定保留。
- 没有 read model 的工具仍使用诚实空态，不为了卡片外观伪造库存。

### 10.2 平台

Windows 与 macOS 使用相同 Renderer 布局引擎，只在修饰键和现有桌面能力上区分。

Web 端可以完整使用布局；终端或观察能力不可用时继续显示现有不可用说明。

不为此改造新增 Host query／command，不改 Runtime overlay 或 transport 契约。

### 10.3 性能

- 拖动预览每帧最多一次几何更新。
- 不在 pointermove 中序列化布局或写存储。
- 不让拖动引起整个对话／Composer 重绘。
- 隐藏模块暂停不必要的观察和绘制，保留业务资源。
- 测量集中处理，避免 ResizeObserver 循环。
- 小尺寸变化与浮窗移动不能清空对话高度缓存。
- 真实内容移动过程中不出现空白一帧、旧位置残影或焦点丢失。

## 11. 分阶段实施与验收

| 阶段 | 工作内容 | 完成标准 |
|---|---|---|
| P0 | 全应用标签视觉 | 代表页面、主题、密度、溢出与键盘焦点检查通过 |
| P1 | 面板抽离、注册表、稳定宿主 | 保持现有布局可用，工具移动验证无重挂载 |
| P2 | 四区、拖动、分组、卡片、浮窗、BTW | 五种位置互移、分组上限、紧凑覆盖与最小化完整可用 |
| P3 | 保存、预设、迁移、菜单和设置 | 会话隔离、继承、默认作用域和找回路径验证通过 |
| P4 | 全面回归、性能与文档 | 验收矩阵通过，限制和证据记录完整 |

每阶段独立提交，保持可编译、可运行。不得将缺少保存、找回或基本键盘入口的中间实现宣称为完整交付。

### 11.1 自动化验收

至少覆盖以下真实行为：

1. 单模块跨五种位置移动，始终只有一份内容。
2. 整组移动、合并、拆成卡片、移空组。
3. 两组上限及分隔比例恢复。
4. 拖动取消、修饰键禁用吸附及释放恢复。
5. 卡片折叠、手动高度和恢复自动高度。
6. 卡片滚动时正文裁剪与点击区域正确。
7. 紧凑图标及覆盖展开不改变对话宽度。
8. 浮窗夹取、最小化、最大化和还原。
9. A/B 会话布局隔离。
10. 新会话默认、项目继承、已有会话无记录、草稿转正式和分支会话。
11. 自定义预设管理、默认引用回退、旧布局一次性迁移。
12. 布局撤销不会影响文本编辑撤销。
13. 隐藏终端不销毁进程；移动可见观察模块不误断开。
14. 已移动工具能被原快捷入口定位。
15. 预览修改不写真实存储。
16. 窄窗临时状态不污染保存布局。
17. 保留原空间预算回归，增加完整列预算测试。

纯视觉样式不写机械式断言；拖动几何和最终行为可用组件测试，真实手感通过浏览器人工验收。

### 11.2 人工验收矩阵

| 维度 | 场景 |
|---|---|
| 宽度 | 1920、1440、1280、1024、800、640px |
| 高度 | 普通窗口、短窗口、高 Composer |
| 主题 | 亮色、暗色 |
| 密度 | compact、standard、cozy |
| 语言 | 中文、英文及长标签 |
| 输入 | 鼠标、触控板、纯键盘 |
| 对话 | 贴底流式、中部阅读、长消息、工具卡展开 |
| 模块 | 文件树、Git diff、Terminal、Browser、Computer、Agents、BTW |
| 浮层 | 多浮窗、胶囊、图标覆盖层、菜单、模态框叠放 |
| 生命周期 | 会话切换、页面往返、重启恢复、归档、删除 |
| 平台 | Windows、macOS；Web 布局与不可用能力说明 |

重点观察：

- 原位置是否留下可点击幽灵区域。
- 拖入卡片后工具栏是否挤出边界。
- 终端是否失去输入、滚动或选择状态。
- 浏览器观察是否因移动而意外停止。
- 对话是否跳位。
- 自动紧凑后放宽是否恢复。
- 浮窗是否压住菜单或模态框。

### 11.3 检查与交付记录

按阶段运行：

`npm run check -- --only renderer`

最终运行适当的架构检查与生产构建切片。现有检查通过后，只有新增改动或发现问题才重复测试，不无理由反复跑全量。

交付记录必须区分：

- 自动测试通过的项目。
- 已人工验收的平台和尺寸。
- 无法在当前环境验证的项目。
- 尚未完成的项目。

不能用 Windows 验证结果宣称 macOS 已验收，也不能用模型测试代替真实拖动和保活验证。

同步更新停靠指导文档、功能索引和必要的用户说明。文档应解释用户可见行为，不把内部实现细节堆入产品操作界面。

## 12. 实施默认值与约束优先级

以下属于实施规格中的默认值，并非逐项经过用户单独表决：

- 拖动阈值 6px。
- 分组边缘命中带 24px。
- 工作台标准标签高度 32px。
- 圆角复用当前约 9px token。
- 对话工具区宽度初始 320px，范围 280–480px。
- 大画面卡片初始正文高度 320px，Terminal 正文最小高度 240px。
- 新建两组默认均分。
- 布局撤销深度 20，仅本次运行内保存。
- Ctrl/Cmd+Shift+L 控制对话工具区，F6 切换区域。
- 顶栏显示按钮恢复最近非隐藏模式；首次显示完整列，空间不足自动紧凑。
- 紧凑覆盖层的暂时展开不随会话持久化。

若实测发现某个数值与现有业务组件无法兼容，可以调整该数值并记录原因；不得借此改变用户确认的产品边界。例如不能因为终端较宽就禁止它进入卡片区，也不能把覆盖图标改成占宽侧栏。

优先级为：

1. 用户最后一次明确选择。
2. 本文已确认的产品行为。
3. 仓库真实契约与项目分层要求。
4. 本文实施默认值。
5. 旧指导文档中的参考建议。

- 默认调整只影响当前会话；新会话使用默认，旧会话重新打开恢复自己的布局。

- 先充分讨论边界、人机功效和交互，再形成详细计划。
