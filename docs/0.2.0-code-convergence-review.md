## 3. GPU 状态回退：复现与修复证据

### 3.1 复现（旧实现下先拿到红证据）

用与 `main.tsx` 等价的旧接线（`cached` 初值 L0、`onChanged` 应用但不保存、`matchMedia` 无参重算）写临时用例：

```
✓ legacy entry wiring > keeps the live tier when the OS motion preference changes (it does not)
  initial "L0" → onChanged(L2) → "L2" → media change → **"L0"**    ← 回退发生
```

即：机器刚被 Main 判定为 L2，用户改一次系统"减少动态效果"，界面就退回 L0（视觉降级失效、软合成机器重新开始绘制模糊/阴影）。临时用例在修复后删除，永久覆盖落在 `tierControl.test.ts`。

### 3.2 根因

`apps/renderer/src/main.tsx`（`6ba0a57`）：

```ts
function applyPerformanceTier(snapshot?) {
  const resolved = snapshot?.tier ?? globalThis.ompStudioPerf?.cached?.tier ?? "L0";   // ← 回退来源
  ...
}
perfBridge.onChanged(snapshot => applyPerformanceTier(snapshot));   // ← 应用了，但没有保存
matchMedia("(prefers-reduced-motion: reduce)").addEventListener("change", () => applyPerformanceTier());  // ← 无参 → 读 cached
```

三个问题同源：**没有"当前机器快照"这个状态**。`probe()` 的结果同样只用一次就丢。

### 3.3 修复（`bfa73bb`，PR #20 分支）

`perf/tierControl.ts`：

- `TierState`：保存最新快照；`accept()` 按 `probedAt` 拒绝更旧的结果（`probe()` 与 `onChanged()` 可能交错，旧结果不能把等级改回去）。
- `effectiveTier(machine, motionOff)`：用户偏好是**下限**——L0 → L1，L2/L3 不变；Main 自己给的 `motion: "off"`（L3）同样是下限。
- `startTierControl(env)`：首帧前写等级、订阅 `onChanged`、仅在无缓存时 `probe()` 一次、订阅系统偏好，返回**可释放**的 disposer（接到 `import.meta.hot.dispose` 与 `pagehide`，避免 HMR/卸载后残留监听）。

测试（`tierControl.test.ts`，14 例）覆盖任务要求的全部序列：缓存 L0 → 事件 L2 → 偏好变化仍 L2；L0 → L3 → 仍 L3；缓存 L2 → 事件 L0 → 用 L0；无缓存时探测；探测失败保留；偏好开/关；软合成 + 偏好覆盖；探测与推送交错（旧探测被丢弃）；无桥（浏览器/harness）；dispose 后不再响应。

## 4. 已实施的架构精简

### 4.1 单一等级属性（DOM 状态 3 → 1，等级规则 2 → 1）

```
Electron Main（唯一分级者：GPU feature status / 核心数 / 内存 / 电池）
    │ PerfProfileSnapshot { tier, motion, 证据字段… }   ← 原始证据仍留在诊断快照里
    ▼
Renderer（只做两件事：保存最新机器快照 + 叠加用户减少动效偏好）
    ▼
<html data-perf-tier="L2 L1">        ← 唯一 DOM 契约；值是"包含的层"
    ▼
tiers.css（每条规则一个 ~= 选择器）
```

删除的导出（`perf/tiers.ts`）：`tierOf`、`attributesForTier`、`readTierInput`、`currentTier`、`TIER_ATTRIBUTES`、`TierInput`、`GpuProfile`、`MotionProfile`、`PerfProfile`。
保留/新增：`PERF_TIERS`、`PerfTier`、`PERF_TIER_ATTRIBUTE`、`tierLayers()`、`isPerfTier()`、`applyTier()`、`readTier()`。

为什么用"层集合"而不是让每个规则写三个 `:is(...)`：CSS 不能比较数字，单值属性会逼着每条 L1 规则重复三元素 `:is()` 列表（旧文件 137 行里约 40 行是这种重复）。`data-perf-tier="L2 L1"` 用 `~=` 表达"包含 L1 层"，每条规则一个短选择器，且"用户减少动效不会解除 L2 降级"由数据结构本身保证，而不是靠三处列表同步。

顺带修掉的一处重复规则：`.hist-row` / `.activity-row` 的 `content-visibility` 早已在 `styles/pages.css` **无条件**生效（`auto 45px`），而 L3 规则又把它们列了一遍并改成 `64px`——同一条视觉行为两处维护且互相打架。L3 现在只负责原本没有覆盖的 `.ce-row`。

### 4.2 构建后 CSS 的真实计算样式验证（不是 jsdom）

`outputs/perf-020/probes/tier-computed-styles.mjs`：把**生产构建**的 `dist/assets/index-*.css` 载入真实 Electron 窗口，为每个等级重建一份 fixture DOM 并读计算值：

```
PASS L0 keeps the effect layers :: blur(8px) / rgba(0, 0, 0, 0.5) 0px 2px 8px 0px
PASS L0 keeps full-length animations :: 1.4s
PASS L0 keeps the L3-only list uncontained :: visible
PASS L1 collapses animation durations :: 1e-05s
PASS L1 holds the pulse opaque (no frozen dim state) :: 1
PASS L1 hides the skeleton sweep :: none
PASS L1 makes the indeterminate bar static :: none
PASS L1 keeps the effect layers (motion-only layer) :: blur(8px)
PASS L2 drops backdrop-filter :: none
PASS L2 drops box-shadow :: none
PASS L2 zeroes the blur variable :: 0px
PASS L2 restores the composer focus ring :: solid
PASS L2 hides the decorative heat sweep :: none
PASS L2 keeps L1 rules (animation collapsed) :: 1e-05s
PASS L2 keeps the L3-only list uncontained :: visible
PASS L3 contains the L3-only list :: auto
PASS L3 drops the wallpaper stack :: none
PASS L3 drops the empty-state artwork :: none
PASS L3 keeps L2 rules (no blur) :: none
PASS L3 keeps the focus ring :: solid

20/20 tier CSS checks passed
```

探针本身踩到的两个坑（写下来以免下一个人重走）：隐藏窗口里 Chromium 会推迟既有元素的 style invalidation（`show:false` 时 `.card` 的 `backdrop-filter` 读到旧值），所以必须 `show:true` **并按等级重建 fixture 节点**；`window.evaluate(fn)` 忘了传参会让属性写成 `"undefined"`，规则自然全不命中。

### 4.3 Runtime 验证缓存收缩

`packages/runtime-installer/src/verification-cache.ts`：

| 删除 | 原因 |
|---|---|
| 泛型 `StatKeyedVerificationCache<T>` → `StatKeyedVerificationCache` | 全仓库只有 `<void>` 一种实例化，`value` 从未被读 |
| `StatKeyedVerificationResult<T>`（`value` + `hit`） | 唯一调用方 `await` 后丢弃结果 |
| 公开的 `fresh?: boolean` | 没有生产调用者；它是"让缓存自己绕过自己"的入口，而执行边界已经由 `resolveRuntime` 直接读字节并比对签名摘要 —— 保留这个旋钮只会诱使下一个人把安全检查重新交给缓存 |

**没有删除**（逐条核对 §5.2 的禁止项）：签名元数据验证、`contentSha256` 与签名覆盖摘要比对、执行前后两次内容读、文件身份校验、TTL、安装/激活/回滚/卸载/prune 失效、single-flight、generation 防旧结果回写、失败不缓存。`fresh` 仅保留为**私有**参数，用于"读取期间被 `invalidate()` 打断后重读"这一处内部逻辑。

### 4.4 终端已释放 ID 的生命周期

`#released`（无界）→ `#removing`（仅在 `remove()` 的 dispose 在途期间存在）：

- `remove()` 开始时加入，`#releaseScreen()` 结束时删除；
- 之后到达的数据由既有的"未知会话"守卫拦截（会话已从 `#state` 移除），不需要记住所有历史 id；
- `close()` 不再向该集合填 id（监听器已全部解绑）。

自然退出 / ACK 封口 / 资源释放三个状态**依旧分离**：`#creditsClosed`（不 ACK，但仍可显示尾部输出）与 `#removing`（关闭中，忽略输出）各自独立，没有重新合并。

## 5. 明确拒绝/延后的精简方案

### 5.1 Composer 草稿 Hook（保留现状）

数据：`draftLive`、`draft`、`publishDraft`、`commitDraft`（20 处调用）、`COMPOSER_DRAFT_PUBLISH_MS`、`draftStatusOf` 都在 `WorkbenchCanvas` 内。

不做的理由（不是"懒得改"）：

1. 草稿 state 来自 `useTargetMemory<ComposerSnapshot>("composer-current-draft", …)` —— **按执行目标记忆**。抽出的 Hook 若自带 state 就会丢掉这个语义（切目标恢复草稿），必须把 `setStored` 传进去；那样 Hook 只是把 4 个名字收进一个对象，调用点仍是 `composer.commit(x)`，行数与概念都不减少。
2. 提取必然引入一层"Hook 拥有定时器 + 组件拥有 state"的跨边界所有权，而现在的实现里定时器与 state 在同一个闭包里（`draftPublish.current`），更容易证明"卸载时清理"。
3. 本轮已有一条硬约束：不能改变草稿同步语义（Enter 必须用 live 快照、边界必须立即提交）。收益（可读性）与风险（多一处跨目标恢复的路径）不匹配。

**如果将来要动**：先给 `useTargetMemory` 增加"自带 reducer"的形态，再抽 Hook——那是另一个 PR。

### 5.2 Dock `PanelHosts` 的观察器（保留现状）

`hosts.ts` 的 `MutationObserver` 观察 `document.body`，在回调里**先过滤**：目标在 `.dock-panel-content` 内（流式正文）直接丢弃，属性变化只认 Dock 几何选择器，childList 只认新增/删除的 Dock 节点。也就是说"流式输出每帧 mutate"已经在**调度之前**被丢弃，不会触发布局测量。

没有改成"只观察 Dock 区域"的原因：

- 几何来源有 4 类：slot 尺寸（ResizeObserver 已覆盖）、区域显隐/`data-layout-overlay`（在 `.adaptive-workbench` 上）、浮窗/Rail 的移动、以及节点迁移（折叠卡片时 slot 被换父节点）；
- 缩小观察面要同时覆盖这 4 类，漏一类就是"面板跟随错位"这种难复现的回归；
- 本轮拿不出**可重复**的"每秒 MutationRecord 数 / 实际 `measure()` 次数"对照（要临时给生产代码加计数探针），而没有证据的改动违反本轮原则。

若要做，最小路径是：加一个只在 `import.meta.env.DEV` 生效的计数（records / measures / 丢弃比例），在真机跑流式对话取基线，再评估。
