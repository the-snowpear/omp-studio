# SSH 工作区的 tmux 终端

OMP Studio 可以直接附加远端 tmux 会话。一个 tmux 窗口对应左侧的一个终端标签，窗口内的窗格按远端布局显示为 xterm 分屏。SSH 断开或退出 Studio 后，远端进程继续运行。

## 前提

- 使用桌面版，连接 Linux、macOS 等 POSIX 系统的 SSH 目标，并打开远端工作区。
- 远端安装 **tmux 3.2 或更高版本**。低于 3.2 时提示升级，不切换到其他实现。
- 远端交互程序应使用 UTF-8 locale / 编码（例如 `C.UTF-8`）。tmux 的 `-u` 设置控制客户端，不会修改 vim 等程序自身的编码。
- 非交互 SSH 命令能找到 tmux。Studio 会补充 `/usr/local/bin`、`/opt/homebrew/bin`、`/home/linuxbrew/.linuxbrew/bin`、`$HOME/.local/bin` 和 `$HOME/bin`。安装在其他目录时，请调整远端非交互命令的 PATH。

连接复用该 SSH 目标的认证方式，包括已有的密码认证票据。控制连接使用 `ssh -T` 和管道运行 `tmux -u -C`，不经过 Windows ConPTY，不需要在终端中手动输入控制模式命令。

## 附加和操作

1. 打开工作台底栏终端，点击 **附加 tmux…**。
2. 点击已有会话，或者输入新名称并选择 **新建 / 附加**。名称使用字母、数字、下划线和短横线，最多 64 个字符，不能以短横线开头。名称已存在时直接附加，新建会话从当前远端工作区目录启动。
3. 左侧出现 `tmux · 会话名` 分组。选择窗口后，右侧显示它的可见窗格。
4. 点击窗格输入。工具栏提供向右拆分、向下拆分、新窗口、缩放活动窗格、重命名窗口和结束窗格。拖动分隔线调整大小；聚焦分隔线后也可以用方向键逐格调整。

其他客户端对同一会话的窗口、窗格和布局改动会同步到 Studio。活动窗格的工作目录显示在终端上方。字体与字号沿用 **设置 → 外观与布局 → 字体 → 终端**。

## 关闭、隐藏和退出

| 操作 | 结果 |
|---|---|
| 点击窗口标签的 × | 默认询问「隐藏 / 结束窗口 / 取消」 |
| 隐藏 | 窗口及其进程继续运行，Studio 暂停接收该窗口的输出 |
| 从「已隐藏」中恢复 | 重新显示窗口并同步当前屏幕 |
| 结束窗口 | 终止该窗口内的全部窗格和进程 |
| 工具栏「结束窗格」 | 直接结束活动窗格，这是明确的结束操作 |
| 点击分组头的 × | 分离控制连接，保留远端会话，无需确认 |
| 分组菜单「结束整个会话」 | 二次确认后终止全部窗口和进程 |
| 退出 Studio、关闭桌面窗口或 SSH 断线 | 只分离，远端会话保留 |

关闭窗口时可以勾选「记住选择」。以后可在 **设置 → 外观与布局 → 字体 → 终端 → 关闭 tmux 窗口时** 改回「每次询问」。隐藏状态和连接列表属于当前 Studio 窗口，暂不在下次启动时自动恢复。

断线或分离后，窗格内容保留为只读。点击 **重新附加** 会连接同名会话并替换原分组的位置；**移除** 清理 Studio 中的已结束分组。如果远端会话已被结束，重新附加会创建同名的新会话。

## 输出与恢复

首次附加取回最近 1000 行历史、可见屏幕和光标。vim 等全屏程序的备用屏、应用光标键、键盘模式、鼠标模式、滚动区域、自动换行和光标可见性一并恢复。恢复与实时输出交接时可能出现少量重复内容。

大量输出时，Studio 使用终端 ACK 机制暂停读取 SSH 管道。整个连接共用背压，因此一个高输出窗格可能短暂拖慢其他窗格。如果 tmux 暂停了窗格，界面显示「输出过快，正在重新同步」，待消费积压数据后恢复并重新抓取屏幕。

同一桌面窗口最多有 4 个 tmux 连接，每个连接最多显示 64 个窗格。超出数量的窗格显示「未显示」占位，不创建更多 xterm 实例。普通 Shell 终端的数量限制独立计算。

## 限制

- 目前只附加 SSH 工作区。不支持本机 macOS、WSL 或 Windows SSH 目标；浏览器版没有桌面终端接口。
- 不接管普通终端中手敲的 `tmux -CC`。如果识别到 DCS 包头，会显示提示和「退出控制模式」按钮；按钮发送空行，让 tmux 分离。Windows 本机 ConPTY 可能已经改写或吞掉包头，此时仍可能看到协议原文。
- tmux 自绘的 copy mode、choose-tree、display-panes 和状态栏不会显示。控制模式中的前缀键不能代替 GUI 操作，请使用按钮和菜单。
- 不支持录制 tmux 窗格，也没有新增 tmux 快捷键。多个 Studio 窗口各自建立连接。
- 同一连接的窗口使用同一个 Studio 视口尺寸，以兼容 tmux 3.2。其他客户端也可能影响尺寸；Studio 以 tmux 回报的布局为准，必要时留白、显示提示或滚动，不修改远端 `window-size` 设置。
- tmux 和 xterm 对 emoji、模糊宽度字符的宽度判断可能不同，某些程序可能发生对齐偏差。

全局预览模式提供会话选择器和分屏演示。演示窗格只显示布局、标题和占位，不生成假的 Shell 输出，也不执行 SSH 操作；`marks=off` 时隐藏演示标记和占位文案。

## 开发验证

协议回放覆盖真实 tmux **3.2a、3.4 和 3.7c** 的原始字节，包括中文、emoji、200 KiB 输出、vim、拆分和缩放布局。`scripts/tmux-transcript.mjs` 使用独立随机 socket 抓取，不操作默认 tmux server。

```bash
npm run check -- --only desktop --suite tmux --suite terminal-ipc
npm run check -- --only renderer --suite terminalSessions --suite TerminalPane --suite TmuxWindowView
npm run check -- --production
```

`tmux-real.test.ts` 在本机没有 tmux 时跳过；设置 `TMUX_TEST_SSH=<alias>` 可经真实 SSH 执行，`TMUX_TEST_CONTAINER=<name>` 可选。测试只操作自己创建的随机 socket，结束时清理测试 server。不要把真实主机名、凭据或测试输出加入产品源码。
