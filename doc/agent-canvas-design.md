# Agent 无限画布：设计决定

立项：2026-11-15。产品讨论同步：2026-11-15。状态：**设计阶段，尚未实现**。

本文记录已确认的**目标体验**、OMP 已读到的原生能力、实现建议与待验证风险。已确认的交互不代表 Runtime 已经支持；尤其不能把「跨 Agent 接续」误写成已有能力。标注「推断」「待验证」的内容尚未实测。实现后改写为 as-built，并将落点登记到 [`feature-index.md`](feature-index.md)。

## 1. 目标

与现有**对话工作区并列**，提供一张像 ComfyUI 那样自由、有创意、好玩的 Agent 无限画布。既能可视化一个或多个项目中的 Agent、子 Agent、分支和 worktree，也能直接进行创作、运行、组合和复用：

- 默认围绕当前选中项目展示真实结构；分支、worktree 可选显示，Agent 可筛选；剩余空间可以自由创作。
- 在画布上创建 Agent 草稿，提前写好输入与上下文，自动保存，之后从任意启动入口运行。
- 以有语义的端口和连线表达**提及、共享、接续**，而不是把所有线都视作无差别引用。
- 同时查看和操作多个 Agent，连接文件、Git、网页、工具、消息和其他 Agent 的结果。
- 把分组折叠为组合节点，局部启动，保存为工作流模板或当前工作状态。
- 通过节点状态、连线动效、执行轨迹和侧挂详情卡查看任务进展。

**产品与技术分层：** 上下文引用尽量沿用 OMP 已有的 `@` 与内部 URL；自动接续、跨顶层会话目标 B 的启动、批量起点计算等是后续新增/验证的能力，不能继续以「全部线只翻译成 @」概括，也不预先断言必须/不必新增编排服务。

## 2. 已确认的产品决定

| 主题 | 决定 |
|---|---|
| 定位与入口 | 「工作台」下分「对话」「画布」，两种交互并列 |
| 范围与默认 | 全局画布，可展示多个项目；默认显示当前选中项目节点；分支/worktree 可选显示；Agent 具有独立过滤规则 |
| 自动结构 | Git 项目：项目 → 分支 → worktree → Agent → 子 Agent；非 Git 项目：项目 → Agent → 子 Agent |
| 视觉筛选 | 自动、仅运行、3 天内、7 天内、全部；隐藏只影响展示，不删除节点/连线，也不改变全局启动范围 |
| 创建 | **双击空白直接创建 Agent 草稿**；右键或工具栏「添加」打开所有节点的选择器 |
| 草稿 | 输入和预备引用自动保存；折叠、关闭、离开后仍保留，启动时直接执行保存的任务 |
| Agent 形态 | **精简卡、完整功能卡、独立浮动窗口**自由切换；同一 Agent 不是复制的会话 |
| 卡片适配 | 小、中、大尺寸渐进展示功能；允许多个 Agent 同时展开、独立操作 |
| 智能收纳 | 随缩放简化未固定卡片；支持手动固定，保护正在输入/等待审批的内容 |
| 详情卡 | 可在 Agent 旁打开执行详情卡，不必把主节点持续放大 |
| 连接关系 | 区分系统结构线和用户关系线；不同意图端口至少包括**提及、共享、接续**，具体共享/接续细节按能力验证 |
| 引用入口 | 输入框内 `@`、手动连线、拖拽消息/文字选区/文件；通过 `@` 或拖拽建立引用时自动建立相应可见连线 |
| 胶囊 | 提及等引用关系使用待发/已发/来源更新/始终带上的引用胶囊；执行关系不能套用这套状态 |
| 启动入口 | **单 Agent、选区、分组、全局**四种；单 Agent 启动也能按后续接续线推进 |
| 起点逻辑 | 批量启动只启动范围内可执行的一级**起始** Agent；接续下游依连线规则启动，不因批量按钮直接并跑 |
| 全局范围 | 全画布所有符合条件的 Agent，**包括当前被筛选隐藏者** |
| 默认启动准入 | 有已保存任务的新草稿或有新输入/上下文的空闲 Agent 可执行；空白、运行中、无变化已完成、中止/异常的默认跳过 |
| 少量节点级设置 | 参与全局、仅手动、有更新才重跑、允许重复运行、暂停参与等，避免过度配置 |
| 后续关系 | 由每条连线决定只引用、自动接续或等待确认；共享的详细行为待验证 Runtime 后讨论 |
| 运行可视化 | 节点状态 + 接续连线动效 + 可定位执行轨迹；可减弱或关闭动效 |
| 分组框 | 视觉容器、整组移动、自由摆放/整理、拖入拖出成员、折叠；允许有限嵌套 |
| 组合节点 | 分组可折叠成有端口的节点；跨组连线自动推断输入/输出，允许手动命名、隐藏、排序、合并及调整类型 |
| 分组启动 | 仅启动组内可执行一级起始 Agent；续接节点按连接推进，嵌套分组不粗暴展平 |
| 保存工作流 | 同时支持**可复用模板**和**当前工作状态**（近期结果与进度摘要，不默认完整历史） |
| 模板实例 | 新建独立副本但保留来源模板关联；可手动同步、另存或解除关联 |
| 模板外部连接 | 跨组连接自动转换成模板输入/输出端口，不绑定原项目/Agent；端口保留语义但可以修改 |
| 其他节点 | Git、Changes、文件、网页、终端、工具、便签及手写看板等可放入画布，工具可弹出窗口 |
| 右栏与底栏 | 画布里保留，进入时默认收起，跟随当前选中 Agent |
| 屏外提醒 | 视口边缘提示等待 Agent，点击定位；导航画布图标显示等待数，不强行移动画布 |
| 导航与布局 | 搜索跳转、适应视图、小地图、键盘导航；自动骨架加手动微调 |
| 存储与失效 | Host 持久化画布；归档/被移除 worktree 保留灰化节点，永久删除会话时清理相应连接 |

「自动」筛选指正在运行或驻留的会话、画布创建的会话及从侧栏拖入的会话。**视觉筛选不等于启动准入范围。**

## 3. 画布上的东西

### 3.1 节点类型

| 类型 | 来源 | 引用卡显示 | 功能卡 |
|---|---|---|---|
| 项目 | 工作区列表 | 名称、连接目标、运行数与等待数 | —（只有引用卡） |
| 分支 / worktree | `git.worktrees.list`、分支状态 | 分支名、领先/落后、是否有未提交改动 | Git 面板 |
| Agent（顶层会话） | 驻留会话、会话历史 | 标题、阶段、等待原因、最近一条输出 | 完整对话 + 输入框 + 胶囊托盘 |
| 子 Agent | 会话的 Agent 快照 | 名称、状态、阶段、完成度、实际模型 | 子 Agent 对话 |
| 工具 | 现有 Dock 面板 | 现有的折叠摘要 | 现有面板正文 |
| 便签 | 画布文档 | 前几行文字 | 可编辑正文 |
| 看板 | 画布文档 | 各列计数 | 可编辑看板 |
| 分组框 | 画布文档 | 折叠后显示标题和成员数，连线收束到框边 | —（展开即框本身） |

分组框不仅是视觉容器：还可局部启动、折叠成组合节点、保存模板与当前工作状态。但分组本身**不会自动改变**成员原本的项目、分支、worktree 或工具权限归属（详见 §3.5）。

Agent 的**生命周期**与**显示形态**独立，避免将草稿/运行/展开混为一谈：

- **生命周期**：草稿、空闲/待命、运行、等待用户、完成、中止、异常等。
- **形态**：精简卡、完整功能卡、独立浮动窗口；运行时也可展开，草稿也可收起。
- **草稿自动保存**：输入框、引用及预设内容在折叠、关闭、离开画布后保留。点击启动直接读取保存内容。

子 Agent 默认折叠成父节点上的计数徽标，展开后显示其真实结构。

### 3.2 系统结构线与多意图关系线

- **结构线**：项目 → 分支 → worktree → Agent → 子 Agent，按真实读模型自动派生，不能靠拖线改写归属。
- **关系线**：手动拖线、Agent 输入框内 `@` 或拖拽引用自动产生；端口区分意图。**提及**用于上下文引用，**共享**用于共享关系（更新/权限/快照语义待定），**接续**用于后续运行关系（是否自动、是否等待确认由连接决定）。
- 提及/共享不应默认触发执行；只有按规则配置的接续线参与执行。不能用「胶囊已发送一次」判断接续线是否继续。
- 不同类型连线的视觉语言应清楚，并支持选中后修改意图；自动创建连线时默认如何选类型尚未确认（第 27 项）。

### 3.3 渐进式卡片、缩放与并行

- **精简卡**展示 Agent 名称、模型、状态、进度、最近输出与连接端口。
- **完整功能卡**按尺寸逐步提供输入、核心操作、完整消息、工具调用、审批和设置；大尺寸接近完整对话工作区。
- **独立窗口**提供完整操作能力；多个 Agent 可同时展开或弹出，各自的输入草稿、滚动位置、审批状态与运行过程互不干扰。
- 缩小时自动简化**未固定**卡片；可以固定重要卡片；正在输入、等待审批的卡片受到保护，不会突然被收起。**缩放/收纳仅改变显示，不影响执行、连线或草稿。**
- 菜单、提示气泡、下拉框等浮层不随画布缩放；功能卡内滚动与画布缩放需要区分手势。

### 3.4 弹出为窗口与侧挂详情卡

- 按住 Alt 拖节点，把它拎出画布变成窗口。Ctrl 已经是「暂停吸附」，空格留给平移画布，Shift 留给多选。
- 是移动，不是复制：正文只有一份。画布原位留一张占位引用卡，连线仍接在它上面。关掉窗口或按住 Alt 拖回去，就回到节点。
- 画布占「主区」的位置参与吸附：窗口吸到右半边时，画布视口缩到左半边。
- 画布是主区的第三种内容（单对话、窗口、画布），窗口浮在其上，共用现有窗口管理器（`dock/windows.ts`、`dock/snap.ts`）。
- **侧挂详情卡**可紧挨 Agent 节点开启，查看消息、工具调用、文件或执行结果；它是独立于主功能卡的阅读/操作视图，不必放大主节点。一个 Agent 同时允许几张详情卡仍未定（第 26 项）。


### 3.5 分组框、组合节点与工作流保存

**自由分组：** 分组框有标题、颜色，拖动标题栏可整体移动，拖动内部节点只移动它自己。拖入/拖出调整成员关系；内部默认自由排布，可按需吸附、整理；折叠再展开保留原位置。允许**有限嵌套**（例如总流程 → 需求/实现/测试阶段），确切层数上限待定。分组提供操作边界但不改写原本 Git/工具作用域。

**组合节点与端口：** 分组折叠后成为可连接、可启动的工作流节点。系统从跨组连接推断输入/输出端口，用户可重命名、排序、隐藏、合并输入、选择公开的内部输出，并修改端口用途。折叠不能丢失内部连线及布局。

**两种保存：**

| 保存方式 | 保存内容 | 目的 |
|---|---|---|
| **工作流模板** | Agent 数量/角色、预设输入、内部关系、端口、布局、上下文占位符；**不保存实时会话或完整历史** | 在其他项目和画布重复创建 |
| **当前工作状态** | 结构、当前输入、连接、布局、运行状态、近期结果与进度摘要；**默认不复制全部过程历史** | 记录当下工作现场、以后回来继续 |

未来可单独考虑「完整现场归档」，不等同当前状态快照。保存状态也**不保证 Runtime 中正在执行的进程能原样恢复**。

保存模板时，跨分组边界的连线会转换成工作流输入/输出端口；接口携带原有意图和类型，但不永久绑定当前项目/外部 Agent。添加模板后创建**独立可编辑副本**并保留来源模板标识；允许查看更新、手动同步、断开关联或另存模板，不自动覆盖已定制的实例。

### 3.6 四种启动入口与统一的可执行性

| 入口 | 起点范围 | 约定 |
|---|---|---|
| **单 Agent 启动** | 指定的 Agent | 直接使用已保存输入运行；若后面有接续线，后续依连接规则推进 |
| **选区启动** | 用户框选/多选的一组节点 | 只触发选区中可执行的起始 Agent |
| **分组启动** | 当前分组内的一级节点 | 只触发可执行的一级起始 Agent；嵌套分组视为组合节点，不把成员直接全部摊平 |
| **全局启动** | **全画布** Agent | 包含当前被筛选隐藏的节点，不因视觉筛选漏执行 |

**起始 Agent**：在本次启动范围里，具备执行条件、且无需先等待接续上游的节点。假设 `A ─接续→ B`，另有独立 C：批量启动先启动 A 与 C，**不同时直接启动 B**；B 在 A 满足接续规则后处理。但用户明确点击 B 的「单 Agent 启动」仍可从 B 开始。

**默认准入与少量覆盖：**

| 状态 | 批量启动默认行为 |
|---|---|
| 草稿，已填写任务 | 启动 |
| 空闲，有新输入或新上下文 | 启动 |
| 正在运行 | 跳过，不重启 |
| 空白 Agent | 跳过 |
| 已完成且内容无变化 | 跳过 |
| 已中止或异常 | 跳过，除非明确重新启动或有节点级例外 |

节点可设「参与全局 / 仅手动 / 有新内容才运行 / 允许重复运行 / 暂停参与」等少量选项。要避免全局和接续同时触发 B 两次；输入变化、并发、重试和取消等精确定义待 Runtime 验证。**选区/分组外的接续节点是否继续被触发尚未决定**（§10）。

每条关系可以有自己的后续行为；提及是引用，接续可自动继续或等待确认，**共享的具体语义推迟到实际 Runtime 讨论**。按钮决定从哪里起跑，连线决定后续去向；不能因单点启动而切断后续。

### 3.7 运行可视化

- Agent 节点显示运行状态、进度、当前步骤或等待原因。
- 真正触发接续关系时连线呈现流动/高亮动效；普通提及不伪装成执行路径。
- 留下可回看的执行轨迹，点击轨迹步骤可定位对应 Agent 的消息、工具或结果。
- 配合侧挂详情卡、屏外等待标记和画布导航；遵循减少动态效果设置，可减弱/关闭动效。

## 4. 上下文连线

### 4.1 输入框 `@`、拖线与拖拽引用

1. 在目标 Agent 的输入框里输入 `@` 选择其他 Agent、文件或条目。如果指向画布上的节点，**同步创建或关联可见提及连线**，避免引用只有文本而无法追溯。
2. 也可从来源节点/条目的输出端口拉线到目标 Agent，明确建立一条关系。
3. 允许将来源 Agent 的**整条消息、选中的文字、文件或工具结果**拖到目标 Agent 输入框或对应端口；落下后生成引用胶囊，并**自动创建或复用连线**。
4. 胶囊可留在输入框下方，或拖入输入框指定位置；没拖入的待发引用在发送时自动附上。发送后的状态仍由 §4.2 控制。
5. 引用动作**不会自行启动目标 Agent**。默认连线类型与松手后的快捷切换尚未确认（第 27 项），不能提前写死。

对话模式下，现有文件 `@`、Git/网页「加入输入框」依旧直接送至当前输入；画布里没有唯一目标输入框，因此工具内选中的条目可成为「已选中引用」并展示输出端口，由连线明确目标。打开文件、查看 Diff 等其他点击行为不变。

**胶囊的已发/更新机制只适用于引用关系；接续关系有独立的待触发、运行、等待、完成状态。**

### 4.2 胶囊状态

| 状态 | 外观 | 发送时 |
|---|---|---|
| 待发 | 正常 | 自动带上，或按拖入位置插入 |
| 已发 | 变灰，留在托盘 | 不带；可手动再拖入 |
| 来源已更新 | 重新点亮 | 自动带上 |
| 始终带上 | 带固定标记 | 每条消息都带 |

「来源已更新」的判定按类型定：文件看修改时间，Agent 看是否有新的结论。具体信号在实现时确认。

### 4.3 来源到记号的映射

胶囊序列化沿用 `apps/renderer/src/composer/serialize.ts` 的现有规则，画布不自己拼内容。

| 来源 | 记号 | 取值时机 |
|---|---|---|
| 文件、目录、图片 | `@路径` | Runtime 发送时自动读入（文本 5 MB、图片 25 MB 以内，目录列前 500 项） |
| Git 提交 | 现有 `git-commit` 引用标签 | 连线时的元数据快照 |
| PR / Issue | 现有 `github` 引用标签 | 连线时的元数据快照 |
| 网页元素 | 现有 `browser` 引用标签 | 选取时的快照 |
| 同树 Agent 的结论 | `agent://<id>` | Agent 用读取工具自己读，读到当时的最新状态 |
| 同树 Agent 的过程 | `history://<id>` | 同上，精简版对话记录 |
| 对话片段（新增） | 快照引用标签 | 选中时的文字；跨会话也能用 |
| Changes 改动（新增） | 快照引用标签 | 选中时某一轮或某个文件的 Diff |
| Git 未提交状态（新增） | 快照引用标签 | 连线时该分支或 worktree 的改动清单与 Diff |
| 终端输出（新增） | 快照引用标签 | 选中时的那段输出 |
| 便签、看板卡片（新增） | 快照引用标签 | 发送时的内容 |

新增的五类都是文字快照，沿用现有引用标签的编码方式（`composer/referenceCodec.ts`，网页元素引用就是这样带文字的）。Diff 和终端输出可能很长，大小上限以及超限后是截断还是存成产物文件再用 `@` 引用，实现时确定。

### 4.4 Agent 连 Agent：目标行为与原生限制

**产品目标：** A 能引用 B、共享结果或建立接续关系；也能从 A 将整条消息/选区拖给既有的 B。单 Agent 启动后，配置为接续的下游仍然有效。不能把「A 连到已有 B 不做」当作长远产品原则。

**已发现的 Runtime 能力：**

- 同一会话树内可通过 `agent://<id>` 读产出、`history://<id>` 读过程；是否带结论、过程或两者可由用户选择。
- 跨顶层会话已有明确机制主要是 handoff：生成交接文档并以此创建**新会话**；已有 B 的直接跨 Worker 引用及自动接续**尚未证实可用**。
- 能画出关系线不意味着已经能完成端到端执行；跨会话读取、触发已有会话、完成事件、权限、取消、审批、失败恢复均需验证或补齐。

因此产品设计保留关系类型与可操作入口，技术阶段明确标注能力缺口，**既不因当前限制删除设计目标，也不承诺未验证的运行能力**。

## 5. OMP 原生能力调查

读的是上游源码（`omp-patch/vendor/oh-my-pi/packages/coding-agent/src/`）和 overlay。

| 能力 | 位置 | 说明 |
|---|---|---|
| `@` 文件自动读入 | `utils/file-mentions.ts` | 发送时由 Runtime 读入并注入为文件提及消息；解析不到的路径当作普通文字 |
| Agent 产出引用 | `internal-urls/agent-protocol.ts` | `agent://<id>` 读完整产出，运行中返回状态和当前进度；支持按路径取 JSON 字段 |
| Agent 过程引用 | `internal-urls/history-protocol.ts` | `history://<id>` 读精简对话记录；`history://` 列出全部 Agent |
| Agent 间消息 | `irc/messaging.ts` | Agent 自己发起和等待，主 Agent 可广播；不是操作者连线能控制的 |
| 交接 | overlay `services/handoff-service.ts` | 生成交接文档并以它开新会话，返回文档和保存路径 |
| 分叉 | overlay `services/fork-service.ts` | 复制历史为新会话 |
| 会话 worktree | overlay `services/session-worktrees-service.ts` | 登记表记录会话对应的分支、路径、基准提交；行状态含未提交改动、有新提交、脱离分支、目录丢失 |
| 派生子 Agent | `contracts/agents-jobs.ts` 的 `agent.spawn` | 可带任务说明、任务文件、上下文、隔离方式、模型 |
| 驻留会话总览 | `client-contract` 的 `ResidentsReadModel` | 每个会话的阶段（空闲、运行、压缩、等待）和等待原因（审批、提问、计划） |
| Agent 快照 | `StudioAgentSnapshot` | 父 Agent、状态、阶段、完成度、用量、实际模型、分支名、是否隔离 |

现有引用/交接能力**不等于**四种启动入口、接续触发、跨会话调度已经可用；这些属于待验证的产品新增需求。另有两条已识别限制：

- **跨顶层会话引用不通（推断）。** 每个驻留会话有自己的 Worker（`studio-host/src/session-broker.ts`），而 `agent://` 的登记表在 Runtime 进程内。
- **没有会话分叉的来源字段。** `client-contract` 里没查到，只在会话列表信息里看到「续接自哪个会话」。

## 6. 落地思路

### 6.1 Renderer 与体验复用

- 新模块 `apps/renderer/src/canvas/`：视口、结构层、意图端口与关系线、自由布局、分组/组合节点、运行轨迹和画布本地状态。
- 「工作台」导航增加「对话」「画布」两个子入口。
- 画布作为 Dock 的新主区形态；完整卡、工具节点和浮动窗口复用既有面板与对话主体，而不是重写一套编辑器。
- 多个 Agent 可并行展开；尺寸渐进适配、固定卡片、输入/审批保护、侧挂详情卡都须明确焦点和层级。
- `@`、拉线、消息/选区拖拽都应收敛成同一套可追踪连接与引用胶囊，引用序列化继续沿用 `composer/`。
- 现有 Dock 工具默认属于某一会话、同一区域通常只开一个实例；画布需容许跨 Agent/分支的多个实例，且分组不能隐式改变工具原作用域。

### 6.2 画布文档（概念草图，**不是已定协议**）

结构节点/结构线继续从读模型派生；存储用户布局、画布草稿、关系类型、分组和运行偏好。旧 `version: 1` 草图中「只有上下文线」「纯视觉 groups」无法表示本轮产品决定，需要迁移方案。以下类型仅表达信息边界：

```ts
type CanvasDocument = {
  version: 2; // 示意版本，具体字段和迁移待实现时定
  viewport: { x: number; y: number; zoom: number };
  visibleProjects: string[];
  filter: "auto" | "running" | "3d" | "7d" | "all";
  structureVisibility: { branches: boolean; worktrees: boolean };
  placements: Record<string, {
    x: number; y: number; width?: number; height?: number;
    form?: "compact" | "full" | "window"; pinned?: boolean;
  }>;
  nodes: Array<{
    id: string; kind: "agent-draft" | "tool" | "note" | "board";
    payload: unknown;
  }>;
  agentDrafts: Record<string, { text: string; references?: unknown[] }>;
  runPolicy: Record<string, "default" | "manual-only" | "repeat" | "paused">;
  groups: Array<{
    id: string; title: string; color: string; members: string[];
    parentGroupId?: string; collapsed: boolean;
    exposedPorts?: unknown[]; templateSourceId?: string;
  }>;
  connections: Array<{
    id: string;
    from: { node: string; item?: unknown; port?: string };
    to: { node: string; port?: string };
    intent: "mention" | "share" | "continue";
    behavior?: unknown; // 共享和接续的细节待能力验证
    sent?: { at: string; revision?: string }; // 仅引用类连接
  }>;
};
```

工作流模板库、模板实例来源、当前工作状态摘要、Agent 原生会话历史及执行轨迹应区分保存职责；**保存画布快照不等于恢复仍在运行的 Runtime 任务**。

### 6.3 Host、Runtime 与协议

- 画布文档读写由 Host 服务实现；按现有项目约定在服务边界集中校验，facade 和 Renderer 不重复做结果校验。
- 新 query / command 先更新 `client-contract/src/operations.ts` 契约，再接 facade 与实现。
- 需要验证或扩展的能力：画布草稿持久化、项目/分支归属读模型、原生引用和跨顶层会话结果读取、对已有 Agent 的接续启动、起始节点识别与批量启动、完成/失败/等待事件、幂等/取消/重试、运行轨迹。
- 分组局部启动、有限嵌套、端口映射、模板实例及版本来源、近期结果摘要恢复各自需要可验证的数据边界。
- 是否需要额外 Host 协调服务由实际能力测试决定；既不预设完整 Runtime 编排引擎，也不把所有执行语义错误归结为胶囊序列化。

### 6.4 预览模式

- 预览开：画布用演示 fixture，放在 `apps/renderer/src/preview/`，沿用现有会话故事，不另起一套。
- 预览关：只显示 Host 真值；没有项目或没有会话时是诚实空态。
- 演示画布的拖动、连线、新建只改本地状态，不调 Host，不写真实画布文档。
- `marks === false` 时不显示演示标记。

### 6.5 其他约定

- 动效只用 `styles/tokens.css` 和 `styles/motion.css` 里的数值和模式；减弱动效时平移和缩放直接跳到末态。
- 普通单选用 `AppSelect`。
- Renderer 不直接 import Node 或 electron。

## 7. 确认程度与交互默认项

### 7.1 讨论已确认

- 默认显示当前项目；分支、worktree 可选；Agent 可筛选并自由摆放。
- 双击空白创建 Agent 草稿，右键/工具栏添加其他节点；输入自动保存。
- 单节点、选区、分组、全局四入口；批量启动只触发可执行的一级起始 Agent，全局包含视觉隐藏者。
- 连线至少区分提及、共享、接续；单点启动也尊重后续接续。
- 分组支持自由移动与整理、折叠成组合节点、端口暴露、局部启动、有限嵌套；支持模板与工作状态两类保存。
- Agent 支持精简、完整、浮动窗口三种形态，渐进展开，多卡并行、智能收纳和手动固定；可打开侧挂详情卡。
- `@`、拉线、拖拽选区/消息产生可见关系；运行状态、路径动效与执行轨迹并存。

### 7.2 仍属建议，不能混作决定

- Git/非 Git 画布按仓库类型自动判断及分支默认收起策略。
- 新 Agent 默认挂最近项目/分支，等待审批是否可直接在精简卡处理。
- 画布的默认滚轮/平移/触控板手势；有限嵌套的具体层数上限。
- 当前「共享」线和接续等待条件的详细行为仍需在 Runtime 可行性讨论后确定。

## 8. 待验证风险

1. **跨顶层 Agent 引用与接续**：`agent://` 等跨 Worker 能力尚未实证，向已有 B 传递结果并触发运行不能当作已有功能。
2. **批量启动语义**：多条入边、汇合、环形接续、正在运行节点、异常/重试、跳过与去重；必须避免全局和上游同时重复触发同一 Agent。
3. **局部执行边界**：选区/分组启动的接续是否继续到选区/分组以外，待产品定案。
4. **共享语义和自动连线默认行为**：共享的实时/快照/权限/更新，以及拖拽后的关系类型选择尚未定。
5. **当前状态恢复**：工作状态保存近期结果和进度，不保证能够恢复原 Runtime 进程或全部历史。
6. **自由缩放与活卡片**：终端、编辑器、对话虚拟列表依赖像素测量；用探针比较 CSS `transform` / `zoom`，并关注指针偏移。
7. **网页节点**：Desktop 的 `WebContentsView` 不随 DOM 缩放，移动时可能要先用静态预览。
8. **跨项目/远程 worktree**：目标 Agent 的工作目录与文件引用权限、失效后的降级需要验证。
9. **多卡并行与执行规模**：订阅数量、全局启动并发、轨迹存储、隐藏节点运行时通知及渲染性能需限制。
10. **存储迁移与失效处理**：旧纯视觉分组/单一关系线模型需要迁移；删除/归档的节点、模板来源失效不能错误重绑定。

## 9. 搭建顺序（建议，非发布日期承诺）

保留原计划「地图与对话、创建与上下文连线、工具与弹窗、便签与看板」的第一版方向，分阶段做可验证的端到端切片：

1. **缩放与交互探针**：多张完整卡、终端、网页、侧挂详情卡、固定卡、审批保护和焦点。
2. **地图与 Agent 操作**：项目结构、可选层级、筛选、导航、三种形态、双击草稿及自动保存。
3. **多意图连接与引用**：端口、`@` 产生可见连线、拖拽引用与胶囊；验证跨会话差异。
4. **运行入口和轨迹**：单节点、选区、分组、全局起点规则；先验证最小接续闭环，再扩展等待/失败、动效和可追溯历史。
5. **组合工作流**：工具、便签、看板、分组/折叠/整理、端口映射、有限嵌套与分组启动。
6. **模板复用与恢复**：保存结构模板、独立实例及来源关系；工作状态摘要、更新检查与恢复边界。

## 10. 待打磨（本轮暂不继续问）

**尚未决定的三项：**

- **26｜侧挂详情卡数量**：每 Agent 一张、多张，或默认一张但允许拆分。
- **27｜自动连线默认关系**：默认提及、每次弹出选择，或默认提及并提供快速切换。
- **28｜复杂图的连线简化**：全显、缩放简化、还是关系筛选 + 焦点高亮；中继点也未确认。

**其他待讨论/验证：** 共享线精确行为；接续跨选区/分组边界与多入边汇合；分组嵌套上限和端口映射；工作流快照恢复粒度；引用胶囊超限处理；具体卡片尺寸、侧挂层级、编辑撤销/重做、同时活卡片上限、触控板操作。
